# T-155 — Feature cards on the logged-in home: dismissible, and they retire to an icon by the bug icon

Engine: claude
Model: sonnet
Lane: web
Context: standard
Touches: apps/web apps/api packages/ui docs
Needs: none

## Why

New capabilities land constantly and users never hear about them. Kumar's direction (2026-11-24, immediate set): the logged-in home gets nice feature cards announcing what's new; a user can dismiss a card, and dismissal doesn't bury it — the card retires to an icon that sits next to the existing bug icon, so the announcement stays one click away without nagging.

## Build

1. **A feature-card registry.** Cards are defined in one small registry (id, version, title, one-paragraph body, optional link to the feature or docs, optional illustration/icon key). Adding a card later is a registry entry, not new UI code. Seed the registry with two or three real recent features (e.g. spreadsheet import with AI mapping, pack illustrations, scorecard-led model picking — builder picks accurate ones; no invented features).
2. **Home placement.** Cards render on the logged-in home in a tidy stack/rail that doesn't push the user's actual work down the page: at most two undismissed cards visible at once, newest first; further cards queue behind the icon with a count.
3. **Dismiss → icon.** Each card has a dismiss control. Dismissing persists per user (server-side, so it follows the user across devices — not localStorage). A dismissed card moves to an icon button placed immediately next to the existing bug icon in the app shell; the icon shows a count badge when dismissed-but-unread cards exist. Clicking the icon opens the card list (popover or panel) where any card can be re-read and its link followed. Reading a card from the icon clears its badge.
4. **New cards resurface properly.** A card with a new version (or a brand-new card) appears on the home again even if an older card was dismissed; a dismissed card never reappears unchanged.

## Guardrails

- No marketing claims beyond what the feature actually does (the standing honesty bounds); cards describe shipped features only.
- Dismissal is per user, never per org — one colleague dismissing doesn't hide the card from another.
- The icon must not collide with or move the bug icon; the shell layout otherwise stays as it is.
- No analytics or tracking in this task.

## Checks

- Tests: dismiss persists across sessions (server state), badge count behaviour, new-version resurfacing, two-card home cap.
- Screenshots: home with cards, home after dismissal showing the icon beside the bug icon, the reopened card list — desktop and mobile widths.

## Acceptance

- A user landing on the home sees what's new, can dismiss it in one click, and can always find it again from the icon next to the bug icon — and a genuinely new feature still gets its moment on the home.
