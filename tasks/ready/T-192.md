# T-192 — Site analytics: allow the Cloudflare beacon in the CSP and pass its token at build

Engine: codex
Model: sonnet
Lane: platform
Context: light
Touches: infra/cdk .github/workflows .env.example
Needs: T-085
Checks: pnpm lint && pnpm typecheck && pnpm test

## Why
T-085 wired Cloudflare Web Analytics into the marketing site (Kumar's pick, 2026-11-28): `apps/site` renders the beacon when `NEXT_PUBLIC_CF_BEACON_TOKEN` is set. Two pieces sit outside that task's Touches, and the beacon cannot run without them:

1. **CSP:** `infra/cdk/lib/site-stack.ts` `CONTENT_SECURITY_POLICY` has `script-src 'self' 'unsafe-inline'` and `connect-src 'self'`, so the browser blocks the beacon.
2. **Build setting:** `.github/workflows/site.yml` does not pass the token.

## Scope
- `CONTENT_SECURITY_POLICY`: add `https://static.cloudflareinsights.com/beacon.min.js` to `script-src` and `https://cloudflareinsights.com` to `connect-src`. This is the production site only; environment copies never get a token, and the extra origins stay harmless there. Source: <https://developers.cloudflare.com/web-analytics/faq/> ("What do I need to add to my Content Security Policy").
- Update `infra/cdk/test/site-stack.test.ts` to assert both entries and that nothing else is loosened.
- `.github/workflows/site.yml`: add `NEXT_PUBLIC_CF_BEACON_TOKEN: ${{ vars.SITE_CF_BEACON_TOKEN }}` beside the other `NEXT_PUBLIC_*` settings. Do not add it to `deploy.yml`, because environment copies stay unmeasured.
- `.env.example`: add `NEXT_PUBLIC_CF_BEACON_TOKEN=` with a one-line explanation in the site section (public token; unset = no script).

## Out of scope
- The app's CSP. Analytics is never in the app.

## Acceptance
- `cdk synth` shows the two new CSP origins on the site distribution only.
- A production site build with the variable set serves the beacon with no CSP violation (checklist in `docs/runbooks/site-analytics.md`).
