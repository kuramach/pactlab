# T-094 — Always-on AI: queued AI jobs, retries, model fallback, circuit breaker and alarms

**Lane:** platform
**Context:** deep
**Touches:** packages/ai, apps/api (ai, documents, findings), apps/worker, apps/web (AI status and drafting states), infra/cdk (alarms, task-role policy test), docs (ADR 0007 addendum, runbook)
**Needs:** T-070 for the deployed parts (ECS task role, CloudWatch alarms). Parts 2–4 run locally first and can start before it.

## Kumar's ask (2026-10-27)

Local testing hit "AI is unavailable: this environment's AWS sign-in has expired or was refused." — "In production, we can't have this since it needs to stay alive. How can we design this for consistent and always available state?" Design agreed the same day; recorded in the ADR 0007 addendum.

## Part 1 — Workload identity, never a human sign-in (with T-070)

- API and worker tasks call Bedrock with an **ECS task role**: `bedrock:InvokeModel` / `bedrock:Converse` (and the streaming variants if used) on the configured inference profiles and their underlying foundation models only. The SDK default chain picks the role up and refreshes it; no code change.
- CDK assertion test: deployed task definitions carry no `AWS_PROFILE`, no `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY`, and the task role's Bedrock statement is scoped (no `bedrock:*`, no `Resource: *`).
- Startup check in deployed environments: one cheap Converse call (or `pnpm ai:check` equivalent) at boot, logged as healthy/unhealthy with the error class only.

## Part 2 — Resilient gateway (packages/ai)

- **Retries:** transient classes already mapped in `bedrock.ts` (throttling, quota, service unavailable, internal, model timeout/not ready, abort/timeout) retry with exponential backoff and full jitter, bounded attempts and a total deadline. Auth and validation classes fail fast.
- **Fallback route:** each prompt route may name a fallback inference profile (a second Claude model, or the same model's other cross-region profile). Fallback is used only for transient classes, only for prompts whose eval suite has passed on the fallback model, and the run record stores which model answered. Never a non-Claude model.
- **Circuit breaker:** after N transient failures in a window, the gateway opens for a cool-down, then half-opens with one probe. While open, calls fail fast with a typed `AI_DELAYED` result instead of hanging requests.
- Unit tests for each path with a fake transport; no outbound calls in CI.

## Part 3 — AI work as idempotent jobs (worker)

- Drafting findings from documents, document Q&A, contract extraction and other model calls move from the request path to BullMQ jobs, keyed by (deal, document hash, prompt version) so a retry or double click never creates duplicate drafts.
- Jobs retry with backoff through gateway outages; exhausted jobs land in the existing dead-letter queue with the error class, and can be re-queued by an operator.
- API returns the job id immediately; existing tenancy, RLS and data-class rules apply inside the job exactly as in the request path (prohibited classes never reach the model).

## Part 4 — Graceful degradation (web + API)

- AI status endpoint reports `AVAILABLE` / `DELAYED` / `OFF`; the UI shows "Drafting…" for queued jobs and "AI is delayed — your requests are queued" while the breaker is open. No blocking error for the reviewer.
- Everything that does not need the model keeps working during an outage: evidence, imports, deterministic pack checks, metrics, valuation, review. Test that explicitly with the gateway forced open.
- Local only: when the error class is an expired/refused sign-in, the message names the fix (`aws login --profile …`) — dev environments only; deployed environments never show operator commands.

## Part 5 — Monitoring (with T-070)

- CloudWatch metrics from the gateway: calls, transient failures, fallbacks, breaker state, queue age of AI jobs. Error class only — never prompts, document text or output.
- Alarms: AI error rate above threshold for 5 minutes; oldest AI job older than 15 minutes; breaker open longer than 10 minutes. Routed to the operator channel defined in T-070.
- Runbook `docs/runbooks/ai-availability.md`: what each alarm means, how to check Bedrock service health and quotas, how to re-queue dead-lettered AI jobs, how to request a quota increase.

## Out of scope

- Provisioned throughput purchase (decide once usage is measured; paid).
- Any non-Claude provider.
- Longer local SSO sessions — an account setting, not code.

## Checks

- `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm test:integration`, `pnpm test:e2e`, AI eval suites for any prompt given a fallback model.
- Integration: a drafting job survives an injected transient outage (fake transport) and produces exactly one set of drafts; a forced-open breaker leaves imports, checks and valuation working.
- CDK: `cdk synth` plus the task-role/no-static-credentials assertion test (no deploy before T-070).
