# T-092 — Failed-deal case library: famous failures as synthetic regression cases, starting with Kroger-Albertsons

**Lane:** demo-data
**Context:** deep
**Touches:** demo-data, packs, domain, docs
**Needs:** T-091 for Case 1's regulatory findings (the rest of Case 1 runs on existing machinery) — build the two together

## Kumar's ask (2026-10-26)

Following the Kroger-Albertsons analysis: encode the lessons so the packs are *tested against history*. A platform that claims to find what kills deals should be required to find it in the most documented deal failure of the decade — with the defects planted at realistic subtlety, and the expected findings written down in advance.

## The case format (the library's unit)

A **case** is four things, versioned together:

1. **Narrative brief** — what really happened, from public sources (court rulings, FTC filings, reputable reporting), cited. Real company names live *only here*, as history.
2. **Synthetic dataset** — two fictional companies and a fictional deal, strictly synthetic (per the standing demo-data rules), shaped so the real case's failure modes exist in the data at realistic strength: findable by analysis, invisible to skimming.
3. **Findings key** — the defects the platform *must* surface, each with expected phase (Pre / Diligence), expected direction, and minimum severity. Written before the run, not rationalized after.
4. **Regression test** — automated: load the case as a demo pact, run the pipeline, assert the key findings surface in the expected phases. A miss files as a product finding against the responsible module/pack — misses are the library's purpose, never quietly re-keyed away.

Cases also load as ordinary demo pacts (sales demos, T-090 training): "run the deal that failed, watch it get caught" is the single best demo this company owns.

## Case 1 — Kroger-Albertsons (the grocery case)

- **Fictional pair:** two regional-to-national grocery chains (names invented at build), overlapping footprints in ~40 local markets.
- **Planted defects (the findings key), 1:1 with the court record:**
  1. *Overlap pockets* — a set of local markets where the pair are the only full-service competitors (Pre; T-091 screen).
  2. *Unused cap headroom* — merger agreement fixture (via T-089 redline/document fixtures) with a 650-unit divestiture cap; the offered package uses materially fewer (Diligence; covenant tracker).
  3. *Cherry-picked package* — divestiture set's performance distribution skews weak vs the retained set (workbench check).
  4. *Incoherent package* — divested assets span banners without shared distribution/systems in several regions (workbench coherence).
  5. *Low-viability buyer* — the remedy buyer is a wholesaler with a thin retail record + a planted precedent flag (a prior remedy failure involving a seller-side party).
  6. *Unaddressed regulator feedback* — two feedback rounds in the document set; round 2's core criticism never answered by a package revision (feedback log aging).
  7. *Unverifiable pledge* — a headline price-investment promise with no measurement or enforcement mechanism (commitment quality).
  8. *Labor exposure* — high union density + overlapping CBAs in the overlap markets (Pre screen).
- **Calibration rule:** each defect is planted at the strength the real record supports — the headroom gap, the skew, the buyer's record are sized from the public facts, not caricatured. If the platform catches a defect only because it was planted loud, the case gets rebalanced, not the key weakened.

## Library roadmap (format proof, not scope creep)

Case 1 ships in this task. The format doc names the next candidates and what each tests, for later tasks: **JetBlue/Spirit** (market-definition fights, no viable remedy shape), **Adobe/Figma** (multi-jurisdiction regulator divergence — US/EU/UK pulling apart), **Illumina/Grail** (closing over objection, then unwind — the Post-phase catastrophe case). One case per future task; the library grows at the rate the lessons are worth.

## Guardrails

- Synthetic data only, per the standing rules; real names and facts appear solely in the cited narrative brief.
- The findings key is fixed before the first run and changes only through a documented recalibration (what was wrong: case or platform — stated explicitly either way).
- Cases are regression assets, not marketing copy: T-088 may demo them, but the library's job is catching platform blind spots; a quarter where every case passes trivially is a calibration smell, recorded in the library doc.

## Acceptance

- Case format documented (`demo-data/cases/README.md`): brief, dataset, key, test — a second case can be authored from the doc alone.
- Case 1 committed: dataset loads as a demo pact; narrative brief cites the public record (Dec 2024 rulings, the efforts-covenant dispute, the $600M fee inside the $9.3B claim).
- The regression test runs Case 1 and reports per-key-item pass/miss by phase; with T-091 built, all 8 key items surface in their expected phases — any miss is filed as a product finding in the PR, not edited away.
- Case 1 is selectable in the demo environment alongside HealthyCo/TroubledCo/SparseCo.
