# T-112 — Trusted devices: longer sign-in sessions on machines the person trusts
Engine: claude

**Lane:** core (auth)
**Context:** deep
**Touches:** db (auth_sessions, auth SECURITY DEFINER functions, organization settings), api (email-login, passkeys, auth guard), web (login, settings), docs (ADR addendum to 0023, runbook)
**Needs:** nothing open. Plan mode first (auth and schema).

Kumar, 2026-11-09: "can we allow for a login session to stay longer on a Trusted machine? If I want 1 day or 1 week, that session shd last so we dont keep login everytime on trusted machines only."

## Today
- Every email-code or passkey sign-in opens an **8-hour** session. The length is fixed in the `pactlab_auth` SECURITY DEFINER function (`interval '8 hours'`), and the web cookie expires with it.

## Decisions (Kumar, 2026-11-09)
- **Lengths:** the sign-in page offers "Trust this device" with **8 hours** (the default), **1 day**, **1 week** or **30 days**. Without trust, nothing changes.
- **Admin cap:** an organization owner or admin sets the longest session allowed (8 hours, 1 day, 1 week or 30 days; default 1 week) in Settings, or turns trusted devices off. The server enforces the cap, and it applies when the session is scoped to that organization.
- **Idle timeout:** a trusted session also ends after **24 hours** without activity. Using it slides the idle window, never past the chosen length.
- **Device list:** Settings → Security lists each trusted device (browser and OS from the user agent, first and last used, approximate location never shown or stored), with **Sign out** and **Sign out everywhere**. Revocation is immediate (checked server-side on every request).
- **Step-up:** sensitive actions ask for a passkey or a new code when the sign-in is more than 8 hours old:
  - inviting people;
  - changing roles;
  - connecting DocuSign or MCP (OAuth consent);
  - billing and checkout;
  - creating promo codes;
  - deleting a pact.

## Shape
- **Database:** columns on `auth_sessions` for `trusted`, `max_expires_at`, `last_seen_at` and `device_label`. The session function takes a requested length, clamped to the cap and to 30 days. Organization setting `max_trusted_session`. Audited: `session.trusted_created` and `session.revoked` (with who).
- **API:** the session token stays short-lived (re-issued from the session row while it is valid), so revocation and the idle timeout take effect within one token lifetime. The step-up guard checks `auth_time`.
- **Web:** a "Trust this device" select on the code and passkey steps, the cookie set to the session's `max_expires_at`, and a Settings → Security device list.

## Acceptance
- **Lengths:** a 1-week trusted sign-in survives a browser restart for 7 days. An untrusted one still ends at 8 hours.
- **Cap:** an organization cap of 1 day clamps a 30-day request to 1 day; "off" forces 8 hours.
- **Idle:** 24 idle hours end a trusted session.
- **Revocation:** "Sign out" and "Sign out everywhere" end sessions on the next request.
- **Step-up:** an invitation from a 2-day-old session asks for a passkey or code first.
- **Tests:** RLS and SECURITY DEFINER tests, API tests, and an e2e for trust-then-revoke.
