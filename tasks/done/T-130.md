# T-130: AI models managed in the admin console
Engine: claude

**Lane:** platform
**Context:** deep
**Touches:** packages/db (ai models), packages/ai (models, gateway, evals), apps/api (ai, admin, documents, foresight, pricing), apps/web (admin, AI messages), infra/cdk (PR 2), docs (ADR 0029, runbook)

## Kumar's request (2026-11-17)

"In the admin, can we add what Frontier models we can add to the pacts? Currently it is code baked in. If a new frontier model comes or an account only wants a certain model, we can control via admin"

Answers:
- **Providers:** other clouds too.
- **Per account:** operators set an allow-list per organization.
- **Safety:** evaluated models only.

## Delivery

- **PR 1:**
  - the catalog, the evaluation gate (the synthetic suite with a pass bar), and platform defaults per role;
  - each organization's allow-list and routes, with `NO_APPROVED_MODEL` when a role is not covered;
  - the provider recorded on every AI run;
  - the admin console tab, and a runbook.
  - Evaluations run in the API process (the worker has no Bedrock access), guarded by a 30-minute lock.
- **PR 2:**
  - ADR 0034 (amends the settled "Claude via Bedrock");
  - OpenAI and Google transports behind `ModelTransport`, with a provider router;
  - credentials in Secrets Manager;
  - a data-terms gate per provider.
