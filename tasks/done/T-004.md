## Brief

Findings are the product. Technology diligence is the first finding factory.

- Findings domain: draft → in-review → accepted/rejected, every transition
  human-approved and audited. AI drafts; humans decide (non-negotiable).
- GitHub fixture adapter (commit history, contributors); live adapter
  config-only.
- Ephemeral scan runner: orchestrator fans out to isolated runners; runners
  return normalized findings only — **source code is never persisted**.
  Prove workspace destruction on success, failure, and timeout (tests).
- One scanner + one SBOM source behind the adapter contract (Semgrep or
  equivalent via fixture; keep the adapter replaceable).
- Technology review UI: findings list, evidence links, priced-risk field
  (a finding carries a proposed valuation adjustment).
- Key-person signals from commit/contribution metadata (aggregates only —
  people-data rules in CLAUDE.md apply).

## Acceptance

- An accepted finding resolves to: commit hash, tool version, evidence item.
- After a scan, no source archive remains on the runner (test).
- TroubledCo ghost commits surface as draft findings.
