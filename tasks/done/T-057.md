## Framework

- **Pack on the deal.** A deal records its pack (software-saas default; one of
  the twelve slugs), set at Start a Pact and changeable by the deal lead with
  an audit event. Downstream logic reads the pack's registry entries — it
  never branches on the slug.
- **Pack registry** (`packages/domain`): per pack — import targets, metric
  calculators, finding types, valuation methods/adjustments, labels. One
  source of truth; the site's `PackDefinition` and the demo data are checked
  against it by test.
- **Import targets.** Generalize `IMPORT_TARGET_DEFINITIONS` beyond
  `BILLING_INVOICE_LINE`: each target has columns, types, required fields,
  aliases, an evidence type and a citation locator. Pack targets reuse the
  upload, preview, mapping, idempotency and lineage code unchanged. People
  extracts (rosters, headcount, per-provider volume) are accepted only as
  aggregates or pseudonymous references; named or compensation columns are
  refused (rule 7) and never sent to a model.
- **Metric calculators.** A versioned calculator interface in
  `packages/calculations` (deterministic, decimal-only, explained inputs);
  the SaaS metrics engine becomes the software pack's calculator without
  behaviour change.
- **Finding types.** A registry of pack finding types with deterministic
  detection rules that propose draft findings citing the imported rows, each
  with a valuation direction (−1 drag priced, 0 neutral with rationale, +1
  confirmed value — never a price increase). Humans decide.
- **Valuation methods.** A method interface in the valuation engine; the
  existing ARR-multiple, DCF and LBO methods register through it unchanged.
  New pack methods (e.g. NOI ÷ cap rate) plug in later.
- **Web.** Pack chosen on Start a Pact; Sources → "Upload pack data" lists the
  pack's import targets with a template download each; Finances shows the
  pack's metrics through the calculator interface.
