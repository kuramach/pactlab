# T-153 — Long card pages (Settings, Admin): a distinct colour per section for eye readability

Engine: claude
Model: sonnet
Lane: web
Context: standard
Touches: apps/web packages/ui docs
Needs: none

## Why

Long pages built from many stacked cards — Settings and the Admin console are the worst cases — read as one undifferentiated wall; the eye can't tell where one section ends and the next begins. Kumar's direction (2026-11-24, immediate set): give each section its own colour so the sections separate visually at a glance.

## Build

1. **A section colour system in the UI package.** Define a small set of section accents (target 6–8) drawn from the brand family — navy/indigo-led, muted, professional; no rainbow, no neon. Each accent is applied the same way everywhere: a coloured section header treatment and a matching left edge or top rule on the section's cards, with the card bodies staying on the standard surface. Text and controls on tinted areas must keep WCAG AA contrast in light and dark themes.
2. **Apply to Settings and Admin first.** Every card group on those pages gets a section accent, assigned consistently (the same section keeps the same colour everywhere it appears). Section-to-colour assignments are defined in one place (a small registry in the UI package) so future pages reuse the mapping instead of inventing new ones.
3. **Make it a reusable pattern.** A `Section` (or equivalent) component/prop in packages/ui that takes an accent key, so any long card page can adopt the system. Apply it to one more long page beyond Settings/Admin if one clearly qualifies (builder's judgment, e.g. the AI models admin page if it isn't already counted as Admin).
4. **Document it** in the UI package docs or the design notes: the accent list, the assignment registry, and the rule that new sections pick the next unused accent rather than reusing a neighbour's.

## Guardrails

- Colour is decoration for orientation only: no meaning is carried by colour alone (section titles remain), no copy or layout changes, no information hierarchy changes beyond the visual separation.
- Brand discipline: accents stay inside the approved palette family; the marketing site is untouched.
- No per-user theming or settings toggle in this task.

## Checks

- Screenshot Settings and Admin (and the third page if adopted) at desktop and mobile widths, light and dark: sections are visibly distinct, nothing clashes, no contrast failures on tinted headers.
- Lint, typecheck and the web test suite green.

## Acceptance

- On Settings and Admin, a user can scan the page and immediately see where each section starts — each section recognisably its own colour, consistently across pages.
