# T-148 — Evaluation citation check: extra cited pages no longer fail a live QA case
Model: sonnet
Engine: claude
Lane: platform
Context: standard
Touches: packages/ai docs tasks
Needs: none
**Needs note:** Kumar's decision, 2026-11-21, on the production evaluation failures of 2026-11-20. The data-terms half of the ADR 0034 gate is untouched; the health-check work on main is a separate thread and is out of scope here.

## Why

On 2026-11-20, production evaluation runs for Haiku 5.5, Opus 5.5 and Sonnet 5.5 each failed twice — every failure a QA case with status ANSWERED and an empty rejected list, failing only on citations: the models cited every expected page **plus extra pages** (notably page 1). Examples: qa.exclusivity expected=[2], cited=[2,2,1,1,2]; qa.change-of-control expected=[3,3], cited=[3,3,3,1] — the identical cited array from two different models. The 5.5 rollout is blocked at the gate on this strictness alone.

The strictness lives in `runQa` in `packages/ai/src/evals/run.ts`: for a live run, `pagesRight` requires both that every expected page is cited **and** that every cited page is an expected page. Kumar's decision: **an extra cited page is not a wrong answer.** Coverage is the requirement; extras are reported, not failed.

## The change

In `packages/ai/src/evals/run.ts`, `runQa`, live branch only:

- `pagesRight` becomes: every expected page is cited (`test.expectPages.every((page) => citedPages.has(page))`). The second conjunct — every cited page must be an expected page — is removed.
- The comment above it (which currently documents "never for a missed or extra page") is rewritten to state the decided rule: a live case fails on a **missed** expected page; extra cited pages do not fail it.
- Nothing else in the case verdict changes: status must still match `expectStatus`, and leaked statements still fail the case.
- The recorded (non-live) path is unchanged — recorded answers still match exactly.
- `citationPrecision` stays computed and reported on the EvalReport exactly as today, and the case `detail` string keeps recording expected vs cited pages — so a model that cites indiscriminately is visible in the numbers even though it no longer fails a case on that alone.
- Extraction cases (`runExtraction`) are out of scope: their drafted-item counts are a different check and are not changed by this decision.

## Tests

In `packages/ai/src/evals/evals.test.ts` (and fixtures as needed):

- A live QA case that cites all expected pages plus an extra page **passes**.
- A live QA case missing an expected page still **fails**.
- Duplicate citations of an expected page still pass (already the behaviour — pin it).
- A recorded (non-live) case with an extra page still fails — the replay path is untouched.

## Acceptance

- The three failure shapes from 2026-11-20 (expected ⊆ cited, extras present, status ANSWERED, no leaks) pass under the new rule when replayed as live cases.
- Full eval suite green; no change to any golden-set case's expected pages (the golden set itself is not edited by this task).
- After this merges and deploys, re-running the Haiku / Sonnet / Opus 5.5 evaluations in Admin → AI models is an operator step (not part of this task) and is what unblocks the 5.5 rollout.
