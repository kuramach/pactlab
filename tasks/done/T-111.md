# T-111 — Batch-load comparables (CSV or paste), not one at a time
Engine: claude

**Lane:** core
**Context:** standard
**Touches:** api (comparables), contracts, web (Comparables page), docs
**Needs:** nothing open. Kumar, 2026-11-09: "We need a way to batch load Comparables. One at a time is slow."

## Shape
- **Comparables page, "Add many":** upload a CSV or paste rows straight from Excel or Google Sheets. A downloadable template has one column per field of the single-entry form (`comparableInputSchema`):
  - kind, name, target, acquirer, date, company type, region;
  - EV, ARR, revenue-or-ARR basis, currency;
  - growth, NRR, GRR;
  - source citation and URL.
- **Preview before anything is saved:** every row is checked with the same schema as a single entry. Each row shows OK or the exact problems (row number, column, message), and rows that look like duplicates of existing comparables (same name, target and date) are flagged.
- **Import:** saves the valid rows, at most 500 per batch, in one transaction (all or nothing). Rows with problems are left out and can be downloaded back as a CSV with their errors, to fix and re-upload.
- **Same rules as one at a time:** the source citation is mandatory, money is decimal (never floats), and permissions are unchanged. The batch is audited (`comparables.batch_imported`, with counts) and each comparable keeps its own creation audit.
- **Nothing new to store:** no schema change, since it goes through the existing `ComparablesService.create` path.

## Acceptance
- **Clean import:** a 50-row template file previews all OK, imports 50, and the benchmark updates.
- **Problem rows:** a file with 3 bad rows (missing citation, a negative EV, an unknown company type) shows those rows with reasons. Importing saves the other rows, and the "rows with problems" CSV round-trips.
- **Paste:** pasting tab-separated rows from a spreadsheet works the same as the file.
- **Duplicates:** flagged, and skipped unless kept explicitly.
- **Isolation and audit:** another organization never sees the rows, and the batch audit event records the counts.

## Built (2026-11-09)
- **API:** `POST /v1/comparables/batch/preview` (nothing saved) and `POST /v1/comparables/batch` (one transaction). Both take the raw CSV or pasted text and parse it on the server with `parseComparableBatch` (`packages/contracts/src/comparables-batch.ts`), which checks each row with `comparableInputSchema`. 422 codes: `BATCH_EMPTY`, `BATCH_TOO_LARGE` (over 500 rows) and `BATCH_NOTHING_TO_IMPORT`.
- **Audit counts:** audit events have no detail column, and this task makes no schema change. So each imported comparable gets its own `comparable.recorded` event, and `comparables.batch_imported` shares their request id; the audit log counts one import by joining on `request_id`. Skipped rows are not saved, so they are not audited.
- **Web:** an "Add many" card on Comparables offers a template download (`/comparables/template.csv`), a file or paste input, a row-by-row preview, "keep anyway" for duplicates, and a download of the rows with problems with their reasons.
