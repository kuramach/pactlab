# T-009 — Caller identity endpoint (API)

Status: ready
Needs: T-002
Touches: apps/api/src/me apps/api/src/auth
Lane: api
Checks: pnpm lint && pnpm typecheck && pnpm test

## Brief

Unblock web sign-in (T-010): the browser must list the signed-in user’s
organizations and permissions, but Auth0’s Management API is out of scope
and the current auth guard rejects tokens without `org_id` — exactly the
state a user is in before picking an organization.

- New module `apps/api/src/me`: `GET /v1/me` resolves the caller from the
  token’s `sub` claim alone and returns
  `{ user: { id, displayName }, organizations: [{ id, name, slug, role, permissions }] }`.
  Permissions derive from the role via the existing `@pactlab/domain`
  role→permission mapping. Never trust client-supplied org ids.
- Auth: extend the guard to attach an *unscoped* principal (subject verified,
  organization null) when a valid JWT carries no `org_id` claim. Add an
  `@AllowUnscoped()` decorator and apply it ONLY to `GET /v1/me`. Every other
  route keeps requiring an org-scoped principal — no behavior change there.
- Resolve the caller with the existing RLS-safe patterns (see how
  `resolvePrincipal` works); the endpoint must function under the runtime
  role.

## Acceptance

- `GET /v1/me` with a valid org-less token returns 200 with the caller’s orgs and permissions.
- `GET /v1/me` with an unknown `sub` returns 401.
- An existing org-scoped route (e.g. `GET /v1/deals`) still returns 401 for org-less tokens.
- `pnpm lint && pnpm typecheck && pnpm test` green.

## Out of scope

- Web UI, Auth0 SDK, login routes (T-010).
- Org member management UI (future task).
