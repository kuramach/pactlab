## Brief

Expand the pactlab.ai marketing site (apps/site, Next.js static export) from the T-017 skeleton into a launch-grade product site that presents Pactlab as a complete, available platform. This site supports the AWS Activate credits application — it must read as a well-thought-out, real product.

## Hard rule

Every feature below is presented as AVAILABLE NOW, in present tense. No "coming soon", no "roadmap", no "in beta", no placeholder sections. If a section exists on the page, it is complete with copy, illustration, and (where specified) an animated demo.

## Content: cover all thirteen modules

One scannable section per module, each with: headline, 2-3 sentence description in brand voice (brand/BRAND.md), and a custom illustration (SVG, brand colors #081127 / #6978ff). Group into four arcs:

**Diligence**
1. Deal context hub — stage, target, team, evidence status in one shell
2. SaaS metrics — CSV/Stripe ingestion, normalized MRR/ARR, NRR/GRR, churn, cohorts, concentration
3. Technology diligence — read-only GitHub/GitLab/Bitbucket connection, code-health indicators, SBOM and license findings
4. OSS and IP risk — license exposure surfaced as priced findings
5. Security and compliance — posture review mapped to findings
6. Team and key-person risk — see "Star players" below; this is a headline feature, not a footnote
7. AI contract review — key terms extracted, deviations flagged
8. Virtual data room — connect your VDR, evidence flows in

**Valuation**
9. Valuation workbench — ARR-multiple, DCF, trading comps, LBO; scenario views with explicit assumptions
10. Risk to valuation — approved findings flow into the valuation bridge and reprice the deal (animated)
11. Cloud and unit economics — infra spend tied to unit economics

**Decision**
12. Priced risk register — severity, confidence, cost-to-fix, time-to-fix, suggested deal consequence
13. Document AI — ask questions across the data room, answers with exact-page citations

**Integration**
14. Post-merger integration — risk-linked 100-day plans exported to your task system
15. Transaction types — public acquirer, private acquirer, take-private; EDGAR ingestion and disclosure-gap analysis for public targets
16. Enterprise SSO — sign in with your company's identity provider (Microsoft Entra ID, Okta, Google Workspace)

## Star players (headline example, must be excellent)

The Team and key-person risk section gets the full treatment:
- Copy: connect any version-control tool (GitHub, GitLab, Bitbucket); Pactlab analyzes contribution patterns and identifies star players — core architects, domain experts, single points of failure — grouped visually by category; flight-risk and concentration feed team-level valuation adjustments ("if the top 3 contributors left, delivery risk reprices the deal").
- Animated GIF `git-stars.gif`: provider logos -> connecting state -> animated contributor constellation graph -> nodes settle into labeled groups (Stars / Core / Supporting / Flight risk). Brand colors, ~800px wide, under 2MB.

## Animated demos (generate with code, commit the GIFs)

Produce each GIF programmatically (Python + matplotlib/Pillow, deterministic seed data, brand colors) under apps/site/public/demos/. No screen recordings, no stock footage. Each under ~2MB, max ~800px wide, with a static poster frame for prefers-reduced-motion:
1. `git-stars.gif` — as specified above
2. `metrics-flow.gif` — CSV/Stripe upload -> normalized MRR ledger -> cohort retention visual
3. `finding-to-valuation.gif` — a finding is approved -> valuation bridge animates -> price adjusts
4. `document-qa.gif` — document upload -> question asked -> answer appears with page citations highlighted

## Page structure

Hero (tagline, pillar, primary CTA) -> "How it works" (evidence -> finding -> assumption -> valuation -> term -> integration action, animated) -> the four arcs above -> transaction types strip -> trust strip (SSO, tenant isolation, audit trail) -> pilot CTA -> footer. Sticky nav with anchor links. Must read well top-to-bottom in one pass.

## Not included

Hosting/DNS, analytics, legal pages, real customer logos/testimonials/statistics, real integration credentials — copy must not invent customers, numbers, or live integrations. CTAs that need real addresses render only when configured at build time (existing T-017 pattern).
