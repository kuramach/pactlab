# T-082 — Real GitHub and Jira live adapters: PRs, reviews, CI, commit messages; Jira Cloud + allowlisted self-hosted

**Lane:** core
**Context:** deep
**Touches:** connectors, domain, api, demo-seed, spec
**Needs:** none — this task unblocks T-074

## Why

T-074 chose live integration-test targets (apache/kafka on GitHub + the KAFKA project on issues.apache.org), but the adapters cannot use them. The loop's agent verified this against the code and Kumar made the decisions below on 2026-10-25:

- `JiraLiveAdapter` is a configuration-only stub (`jira-live-0`): `listIssues()` throws NOT_ENABLED, validation always fails closed. And `jiraConnectionConfigSchema` restricts `site` to `*.atlassian.net`, so a self-hosted Jira cannot even be configured.
- `GitHubLiveAdapter` (`github-live-1`) reads commits only. The `GitHubAdapter` contract is head / listCommits / identityMap; normalized commit metadata drops the commit **message**; required permissions are `metadata:read` + `contents:read`. No pull requests, no reviews, no check runs — so the `KAFKA-####` cross-links that T-074 exists to verify have nothing to attach to.

## Decisions (Kumar, 2026-10-25 — do not relitigate)

1. **Resequence.** This task builds the adapters, planned properly (T-055-style, contract first). T-074 becomes the verification pass against the Kafka pair once these land; its targets and scope are unchanged.
2. **Jira gets a real client, and self-hosted is allowlist-only.** Build the live REST client behind the existing `JiraAdapter` contract (issues via JQL search with pagination; sprints as the contract already models them; the existing credential store carries the token). Extend the site config beyond `*.atlassian.net` ONLY through an **operator-controlled host allowlist** (platform config, e.g. SSM/env — never a value a deal user can type): default allowlist is Atlassian Cloud; named hosts (issues.apache.org, for T-074's test config) are added by the operator. This also closes a real product gap — diligence targets run Jira Server/Data Center, not just Cloud.
3. **GitHub's contract grows up.** Add normalized **pull requests, reviews, and check runs** (metadata level, same discipline as commits: never file contents, diffs, or archives), and **retain commit messages** on commit evidence — messages and PR titles carry the Jira keys. Add `pull_requests:read` and `checks:read` to `GITHUB_REQUIRED_PERMISSIONS`. **Unauthenticated reads are allowed for public repositories** (anonymous rate limits are fine for smoke tests; recorded fixtures carry CI); a private repository still requires a credential and must fail validation clearly without one.
4. **Cross-links are a connector output.** Commit messages and PR titles are scanned for Jira-key patterns (`[A-Z][A-Z0-9]+-\d+`) and emitted as normalized link evidence (commit/PR <-> Jira issue key). Any new evidence types register in `VALUATION_DIRECTION_MAP` — the existing contract test must keep failing the build on unmapped types.
5. **Synthetic data is part of this task.** The HealthyCo / TroubledCo / SparseCo fixture sets (fixture adapters + fixture data) gain matching PRs, reviews, check runs, commit messages with planted Jira keys, and Jira issues that resolve them — so contract tests stay hermetic via the existing cassette infra (`http/cassette.ts`). No test in the PR gate calls the live internet.

## Guardrails

- Read-only, forever: no writes to GitHub or Jira from these adapters.
- SSRF discipline on the allowlist path: HTTPS only, no IP-literal hosts, no redirect following to a different host, and validation rejects any site not on the allowlist with a clear error. Payloads are never logged (existing rule).
- Anonymous GitHub is 60 req/hr: live smoke tests stay tiny and run behind the env flag from T-074, never in the gate.
- Keep the fixture/live config identical in shape (the existing "switching mode needs no code or schema change" property) — the allowlist is config, not a mode fork.

## Acceptance

- Jira live adapter returns real issues for a Cloud site in cassette tests, and for allowlisted issues.apache.org in the flagged smoke test; a non-allowlisted host fails connection validation with a clear, specific error.
- GitHub live adapter returns PRs, reviews, and check runs for a public repo with NO credential (smoke), and for a private repo with one; commit evidence now includes the message.
- Cross-link evidence is produced from fixture data: a commit message and a PR title containing `KAFKA-1234`-style keys yield link records to that issue key.
- `VALUATION_DIRECTION_MAP` covers every new evidence type; connector contract tests + existing github/jira suites pass; fixture-mode behavior for existing consumers is unchanged.
- Spec/ADR note records the contract changes (new normalized types, allowlist mechanics, anonymous mode) in the repo's usual place.
