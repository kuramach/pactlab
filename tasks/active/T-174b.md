## Why
T-174 built the email catalogs and the AI language parameter (ADR 0067) but could not read a stored language or a pact's working language, nor record the run's language: all need `packages/db`.

## Build
1. **Schema (expand only, plan mode first):** `deals.working_language` (nullable, `en|de|fr|ja`, default the organization's), `ai_runs.output_language` / `output_language_written` / `output_language_fallback`.
2. **Emails:** the notification dispatcher, digests, invitations and the remaining templates resolve the recipient's language (`resolveEmailLocale(user.locale, organization.defaultLocale)`); the web sends the page language on sign-in/sign-up start.
3. **Documents:** reports, IC pack, term sheet and LOI in the pact's working language with T-170's formatter in that locale; an embedded CJK-capable font (confirm the dependency) so Japanese never falls back; tests in de and ja with EUR and JPY pacts that the header logo, footer and sender are present; translated drafts labelled with their source language, executed documents never translated.
4. **AI:** jobs a person reads pass the reader's language; the run's language is persisted; the fallback label shown beside the output.

## Acceptance
- A Japanese-locale user in a JPY pact receives sign-in, notification and digest emails in Japanese with yen formatting; a report for a German EUR pact is German throughout, euros de-DE.

- **The database column:** a pact working language and a saved language per AI run (expand-only migrations) are in scope. Add `packages/db` to this task's Touches if it's missing.
