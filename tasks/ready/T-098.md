# T-098 — AI document intake: drop everything in, Pactlab sorts it and asks for what's missing

**Lane:** core
**Context:** deep
**Touches:** domain (packs, imports), db, contracts, api (documents, imports), worker, ai (prompts), connectors, web (documents, overview), e2e, scripts/demo-data
**Needs:** none

## Why (Kumar, 2026-10-28)

Input is the slowest part of a pact. Users shouldn't have to know which file
goes where. In the AI era the flow is: **hand over everything at once**
(many files, or one zip). Pactlab unpacks it, reads each file, decides what
it is and which company or customer it belongs to, files it, and says
plainly what's **missing**. Data that arrives through a connection (GitHub,
Jira, billing, etc.) takes its own path and isn't asked for as documents.

## 1. One intake for everything

- A single drop zone on Diligence → Documents (and on pact creation) accepts
  many files and **.zip** archives. Zips are unpacked server-side: nested
  folders are kept as a hint, nested zips are unpacked one level, junk
  (`__MACOSX`, `.DS_Store`, `Thumbs.db`) is skipped. Every file inside goes
  through the same scan and limits as a direct upload.
- Builds on T-094 B1–B3 (multi-upload, per-file status, auto-extraction). The
  intake reuses those per-file states rather than adding a parallel pipeline.
- Archive limits are stated and enforced, with zip-bomb protection
  (uncompressed-size and file-count caps). A file inside a zip that's
  rejected is listed with its reason. Nothing is dropped silently.

## 2. Classify each file

- AI classification assigns each file a **category** from a pack-aware
  taxonomy, for example: Balance sheet, P&L, Rent roll, CAM reconciliation,
  Customer contract, Lease, Loan agreement, Cap table, Org chart, Policy. Each
  category also says whether it is an **import target** (structured data →
  existing `IMPORT_TARGETS` mapping, e.g. rent roll CSV/XLSX →
  `MULTIFAMILY_RENT_ROLL`) or a **document** (read for findings).
- Each classification shows its confidence and reason ("sheet headers: Unit,
  Tenant, Rent, Lease end"). Low-confidence files land in a short **"Check
  these"** list for one-click confirm or change. A person confirms every
  category before anything is imported into the numbers. High-confidence
  files can be confirmed in one bulk action, but never automatically (rule 2:
  AI classifies, humans decide). Same rule as T-094 B9: an unconfirmed
  extraction never touches valuation.
- Structured files then go straight into the existing import mapping (with the
  mapping suggestion pre-filled). Documents go to extraction. One drop feeds
  both.
- Duplicates (same sha256, or same content in another format) are spotted
  and shown as one.

## 3. Tag to company and customer

- Each document gets an **entity**: which company it's about (target,
  subsidiary, or for portfolio pacts which portfolio company).
- **Customer contracts are tagged to the customer** when it can be inferred
  (counterparty name in the contract, matched against customers already known
  from billing imports or connections). Inferred tags show their source and
  can be corrected. The documents library filters by category, company and
  customer.

## 4. What's missing — ask for it

- Each pack declares its **expected inputs**: required and nice-to-have
  categories (e.g. multifamily: rent roll, T12, delinquency; SaaS: billing
  export, customer contracts for the top N customers, cap table). Packs
  already declare import targets and metrics, so this sits beside them.
- A **checklist** on Overview and Documents: each expected input is received
  (with the files), missing, or covered by a connection. Smart gaps where
  possible: "contracts for 3 of your top 10 customers by revenue are
  missing: Acme, Globex, Initech."
- **Request missing items:** one action produces a request list the user
  can send to the counterparty. In a pact with a seller-side guest (ADR 0014),
  it becomes a request inside the pact, and the seller's uploads fill the
  checklist as they arrive.

## 5. Connected sources take their own path

- When a category is fed by a connection (GitHub → code and delivery,
  Jira → delivery, billing provider → invoices), the checklist shows it as
  **"connected"**: synced, last sync time, coverage. It isn't requested as
  files. If both a connection and an uploaded file exist, the connection
  wins for the numbers and the file is kept as a document.
- Connections are offered at the point a gap appears ("Delivery data
  missing. Connect Jira, or upload an export.").

## 6. Demo data in the same shape

- Restructure `kuramach/pactlab-demo-data` so each pack's scenario ships as
  **what a seller would actually hand over**: one `dataroom.zip` (plus the
  same files unzipped for browsing) of mixed real-world-looking files.
  Balance sheet, P&L, rent roll, customer contracts naming real-looking
  synthetic customers, and so on, with inconsistent file names, a couple of
  deliberate gaps, one duplicate and one misfiled document. Connection data
  (GitHub/Jira from T-094 B8) stays separate, as fixtures loaded through the
  connection path, not inside the zip.
- Each scenario's README lists what intake should find: categories, customer
  tags, the deliberate gaps. That list becomes the e2e expectation. Keep it in
  step with the in-repo synthetic fixtures (T-082 style); regenerate through
  `scripts/demo-data/generate.py`.

## Guardrails

- AI-excluded data classes are never sent for classification. They're filed
  by file name/extension only and flagged for manual categorization.
- Every intake step shows its state per file. A failure is announced when it
  happens.
- Side-scoped confidentiality is unchanged: seller uploads into a request
  land on the seller-visible side unless the buyer imports them.

## Retest checklist

1. Drop the software-saas `dataroom.zip`: every file listed, categorized, with
   confidence. The duplicate is shown once; the misfiled one is in "Check these".
2. Billing export goes into the import mapping. Contracts go to extraction.
   Customer contracts are tagged to their customers.
3. Checklist shows the deliberate gaps by name; "Request missing" produces the
   list; in a pact with a seller guest, the seller uploads one and it ticks off.
4. GitHub/Jira show as connected, not missing. Disconnecting turns them back
   into gaps with "connect or upload" offered.
5. Repeat 1 with multifamily and commercial-property packs: rent roll / T12 /
   CAM classified to their import targets.
