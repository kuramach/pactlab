# T-043 — Evidence browser: real pagination and a record count

Status: ready
Needs: none
Touches: apps/api apps/web packages/db tasks
Lane: web-ux

- Today the evidence browser (`apps/web/app/(app)/deals/[dealId]/evidence`)
  renders one page of rows plus a lone "Next page →" link when a cursor
  exists. There is no total, no position, and no way back — a user cannot
  tell whether a deal holds 30 records or 30,000.
- API: the evidence list response gains `total` — the count of records
  matching the current filters (type, visibility, source record id,
  connection), computed in the `packages/db` evidence list under the same
  tenant/RLS scope as the page query it accompanies. Cursor pagination
  (`after` / `nextCursor`) stays exactly as is.
- Web: the table header or footer shows the total ("342 records") and the
  current window ("1–25 of 342"); a pager with Previous and Next that
  preserves every active filter; Previous is disabled on the first page;
  page size stays the API default limit; changing filters resets to the
  first page.
- Tests: API test asserting `total` equals the filtered row count, including
  a filter that excludes rows; web test rendering the count and pager from
  a fixture response (first page: Previous disabled; later page: both
  directions preserve filters).
