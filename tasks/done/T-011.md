# T-011 — Findings persistence (schema, RLS, repository, mount)

Status: done
Needs: T-004
Touches: packages/db apps/api/src/findings apps/api/src/app.module.ts tasks
Lane: findings
Checks: pnpm lint && pnpm typecheck && pnpm test && pnpm test:integration

## Why

T-004 shipped the findings domain, service and controller against a
persistence *port* only. There are no findings tables, the only
implementation is an in-memory test double, and `FindingsModule` is not
mounted in `AppModule` — `/v1/deals/:id/findings` does not exist on the
running API. Increment 3's exit criterion ("an accepted finding resolves to
commit, tool version and evidence") is unmet on real data.

## Outcome

`POST/GET/PATCH /v1/deals/:dealId/findings[...]` and `/reviews` work on the
running API against PostgreSQL, with RLS-enforced tenant + contributor
isolation, append-only reviews and evidence links, and audit events written
in the same transaction as each change.

## Plan

### 1. Schema (expand-only migration `20261005000000_findings`)

Enums: `finding_domain`, `finding_severity`, `finding_confidence`,
`finding_status`, `finding_origin`, `review_decision`, `priced_risk_type`.

`findings` — one row per finding, mutable only through optimistic concurrency.

| column | type | notes |
|---|---|---|
| id, organization_id, deal_id | uuid | composite FK to `deals(organization_id,id)` |
| domain, severity, confidence, status, origin | enums | |
| title, description | text | |
| fingerprint | text | `UNIQUE (organization_id, deal_id, fingerprint)` — scan replay is a no-op |
| priced_risk_type | enum, null | all-or-none CHECK across the priced-risk columns |
| priced_risk_currency | char(3), null | |
| priced_risk_low / _high | numeric(19,4), null | CHECK `0 <= low <= high`; never JS floats |
| priced_risk_basis | text, null | |
| created_by | jsonb | the `FindingActor` (HUMAN / AI / SYSTEM); CHECK on `kind` |
| evidence_version | int | finding version whose link set is current |
| version | int | optimistic concurrency |
| created_at, updated_at | timestamptz(3) | |

`finding_evidence_links` — **insert-only**. A draft edit that changes
evidence appends a new link set stamped with the finding's new version and
moves `findings.evidence_version`; earlier sets remain as history (no DELETE
privilege exists). Columns: finding_id, finding_version, ordinal,
evidence_item_id (composite FK to `evidence_items(organization_id, deal_id, id)`
— links cannot point across tenants or at nothing), commit_sha (CHECK 40/64
hex), tool_name, tool_version, ruleset_version, path (CHECK
repository-relative), line_start, line_end.

`finding_reviews` — **insert-only** human decisions: decision, from/to
status, reviewer_user_id, reviewer_role (`deal_role`), rationale, decided_at.

All three: `UNIQUE (organization_id, deal_id, id)` and composite FKs, as with
the evidence spine.

### 2. Privileges and RLS

- `pactlab_app`: `SELECT, INSERT` on all three; `UPDATE` on `findings` limited
  to the mutable columns (title, description, severity, confidence, status,
  priced_risk_*, evidence_version, version, updated_at). No DELETE anywhere.
- `ENABLE` + `FORCE ROW LEVEL SECURITY`. Policy on each table:
  `organization_id = app_current_organization_id() AND deal_id = ANY(app_current_deal_ids()) AND app_is_buyer_side(deal_id)`
  — findings are buyer-side analysis; target contributors see nothing even
  if a server check regresses.

### 3. Repository

- `packages/db/src/findings.ts`: row ↔ domain mapping and tenant-scoped
  queries on a `TransactionClient` (same style as `evidence.ts`). Money is
  read back as a scale-4 decimal string.
- `apps/api/src/findings/prisma-findings.repository.ts`: implements
  `FindingsRepository`; every call runs in `withTenant`; `insert`/`update`
  append the audit event in the same transaction; `update` uses
  `updateMany(where: id + version)` for optimistic concurrency. Review
  decisions also enqueue an outbox event (`finding.<decision>`, idempotency
  key `finding:<id>:v<version>`) so downstream staleness (T-012) has a
  durable trigger.

### 4. Mount

`AppModule` imports `FindingsModule.register(new PrismaFindingsRepository(prisma))`.

### 5. Tests

- `findings.api.test.ts` runs against the real app (`createApp`) and PGlite
  with every migration — the in-memory double is deleted. Audit assertions
  read `audit_events`.
- New repository/RLS tests: cross-tenant read/write denied; target
  contributor sees zero rows at the database layer; `UPDATE`/`DELETE` on
  `finding_reviews` and `finding_evidence_links` denied; `DELETE` on
  `findings` denied; link to another tenant's evidence rejected by FK;
  stale `expectedVersion` returns false; fingerprint replay idempotent.
- `rls.integration.test.ts` repeats the cross-tenant findings proof against
  real PostgreSQL.

## Acceptance

- `/v1/deals/:id/findings` served by the production `AppModule`.
- An accepted finding's detail resolves to evidence item, commit SHA and
  tool version from PostgreSQL, with an ordered human review history.
- Tenant B gets 404 on tenant A's findings; target contributor 403 at the
  API and zero rows at the DB.
- Checks green.

until T-012).
