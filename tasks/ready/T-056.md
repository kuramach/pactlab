# T-056 — Many repositories per deal

Kumar (2026-10-22): split out of T-055. A target with thousands of engineers
has hundreds of repositories; today one GitHub connection is one repository
(`repository` in the connection config, ADR 0005). Hold until T-055 lands.

## Outcome

A deal lead connects a seller's GitHub organization once, the seller approves
which repositories Pactlab may read, and every Engineering, key-person and
ghost-commit view covers all of them — with each figure still traceable to a
repository and commit.

## Work

1. **Plan mode first** — this changes the connection model, credentials and
   sync jobs (auth + schema + infrastructure). Amend ADR 0005 or write a new
   ADR before building.
2. **Connection scope.** One GitHub connection covers a set of approved
   repositories (from the App installation's repository selection, or a
   fine-grained token's repositories). Verify every endpoint, permission and
   rate limit against GitHub's current documentation and installed types —
   never assume them. Repository selection is shown to the deal lead and is
   audited; adding or removing a repository is a recorded change.
3. **Sync at scale.** One idempotent sync run per repository as worker jobs
   (BullMQ), bounded concurrency, resumable after failure, respecting GitHub
   rate limits; per-repository status and truncation surfaced on Sources.
   Metadata only — never contents, diffs or archives (rule 5).
4. **Evidence and lineage.** Repository head and contributor activity carry
   the repository; areas become `repository/area`. Contributor keys already
   join across repositories within a deal; keep them deal-scoped.
5. **Findings and Engineering.** Key-person, ghost-commit and licence
   findings, team health, profiles, map and network work across repositories,
   with a repository filter. Reuses T-055's scale design unchanged.
6. **Fixtures.** Fixture GitHub organizations with many repositories
   (including ScaleCo from T-055) and a partial-permission repository, through
   the same adapter contract.

## Tests

- Connection allow/deny paths, repository-selection audit, tenant isolation.
- Replaying a multi-repository sync creates no duplicates; one repository
  failing does not abort the others.
- Engineering totals equal the sum over repositories; findings cite the right
  repository and commit.

## Out of scope

- Bitbucket and GitLab (same pattern, separate tasks).
- Live code scanning across repositories (scanner-orchestrator).
