# T-178 — Pactlab Rinse: the desktop app where the seller rinses the full document set locally, closes the gaps, then uploads the finished folder

Engine: claude
Model: opus
Lane: platform
Context: deep
Touches: apps/desktop apps/web apps/api packages/connectors packages/ai packages/domain packages/contracts docs tasks
Needs: none
Checks: pnpm lint && pnpm typecheck && pnpm test && pnpm test:integration && pnpm test:fixtures && pnpm test:e2e

## Why — and why desktop (Kumar's direction, 2026-11-26, superseding the web-first shape)

Most of the time it is the **seller** who has the documents. So the prep bench is a desktop app the seller runs on their own machine: they drop the whole document set in, the app **rinses** it — converts everything to the standard format Pactlab likes, checks it, and shows every gap — the seller fixes the gaps right there (add the missing statement, re-scan the unreadable page, resolve the duplicate) and only then uploads the finished set to a folder (deal room, OneDrive, Drive, Box, or a plain local/network folder) that feeds the pact. Nothing half-clean ever leaves the seller's machine, and the seller needs no Pactlab seat and never touches the pact itself.

## Build

1. **One cross-platform app.** A Tauri shell (single codebase for macOS, Windows and Linux) in `apps/desktop`, reusing the web UI components for its screens. Signed and notarized builds with auto-update (Tauri updater). **The product's name is Pactlab Rinse** (Kumar, 2026-11-26) — app name, bundle identity and copy use it throughout, with the line "Rinse your deal documents clean before they go in the room." Distribution is a dedicated download page at **pactlab.ai/rinse**: macOS (Apple Silicon and Intel), Windows and Linux installers with the current version, release notes and SHA-256 checksums, free to download; the page ships in the site's locales with T-171, and a prep invite (step 1) deep-links straight to it. The Rinse name joins the open Pactlab trademark-clearance list before public launch. **A Pactlab login is required** (Kumar, 2026-11-26) — the same passwordless email-code / passkey auth as the web app, as a free preparer account. Two ways in: the preparer creates the free account, or the buyer sends a **prep invite** (link/QR from the pact) that creates the account and binds it to the inviting org and deal in one step. The login is what makes the upload trustworthy, and it gates three things: (1) **binding** — the finished set is stamped with the preparer's verified identity and, via the invite, its intended pact, so injection lands in the right deal and provenance names a real party; (2) **the AI rinse jobs** — classification/OCR run under that account (metered, ADR 0034 data terms, abuse control; anonymous AI access is never offered); (3) **upload to a Pactlab-hosted deal room**, when that is the chosen destination. It is not a paid seat and grants no pact access: a preparer login sees only their own bench sets and invites. The seller's OneDrive/Drive/Box sign-in inside the app is a separate auth (their cloud, their account) and never substitutes for the Pactlab login. Offline, a signed-in app still runs the local deterministic rinse from its cached session; AI steps and uploads queue until sign-in/connectivity returns.
2. **Local rinse pipeline (the core loop: rinse → gaps → fix → re-rinse until clean).**
   - *Ingest:* whole folders, bulk files, zip archives; watch-folder mode so files added to a working folder queue themselves.
   - *Convert locally:* every document becomes the canonical form — normalized PDF with extracted text and stable page anchors — using bundled local tooling (office-to-PDF and PDF normalization run on the machine); spreadsheets/statements are **not** flattened — they are flagged and packaged for the guided-import flow (T-152) at injection time. Originals are never modified; converted versions sit alongside them with a per-file conversion log.
   - *Check locally first:* corruption, exact/near duplicates (hashes), readability — deterministic checks cost no model calls and work offline. *When online,* classification into the pack's document taxonomy, metadata extraction and OCR-quality scoring run through the AI gateway as metered jobs under ADR 0034 gates (vision lane for scans); results cache on the machine so re-rinsing is cheap.
   - *Audit the conversion against the original (Kumar, 2026-11-26):* converting is not trusting. For every converted document the app re-reads the **original** independently of the converted text (for scans, the vision lane reads the source image; for native files, the embedded text layer) and compares: **key figures and totals** (statement totals and subtotals, schedule totals, rent-roll sums, cap-table counts), dates and party names, **page-count parity** (every original page accounted for — no dropped pages), and table presence (every table detected in the original exists in the conversion). Tables are also footed inside the conversion: line items must sum to the stated total. Two different failures, kept distinct: a **conversion mismatch** (converted figure ≠ original figure) is an error — it blocks ready until the conversion is fixed or re-run; a **source discrepancy** (the original itself does not foot) is the seller's document being internally inconsistent — it travels as a noted gap and becomes diligence signal at injection, not a conversion error. Every mismatch is shown side by side (original value vs converted value, page on each side) in the review queue. The audit result is written into the manifest per document — figures compared, matched, mismatches and their resolution — so the buyer sees at injection that the set was audited, not just converted. Statements routed to guided import get the equivalent treatment from that machinery (T-152/T-149), and its result joins the same manifest section rather than being duplicated here.
   - *The gap list:* the app fetches the target pack's expected-document list and shows completeness as a checklist — present, present-but-flagged, missing. The seller resolves each gap locally (add, replace, re-scan, or mark not-applicable with a note) and re-runs checks until the set is clean or every remaining gap carries an explicit note. **The set cannot be marked ready with an unresolved error** — warnings and noted gaps can travel, errors cannot.
3. **Upload the finished folder.** One action writes the finished set — originals, converted versions, and a `pactlab-manifest.json` (per-file: classification, metadata, check results, gap notes, conversion log, hashes) — to the destination the seller picks: a local/network folder, or **their own** OneDrive / Google Drive / Box through their own sign-in in the app. Because the destination is the seller's own account, no Pactlab write-access to anyone's cloud is needed on this path.
4. **Injection (pact side, in the web app — unchanged in spirit).** The finished folder becomes pact input two ways: (a) the folder is connected as the pact's document source through the existing read-only OAuth sync (T-147) and the manifest is read at sync time, so classifications, gap notes and provenance arrive with the files; or (b) a one-time import of the folder + manifest. Injection is always the pact-side user's explicit act; every injected document carries its provenance (original file, conversion log, manifest entry) so citations trace back to the seller's original.
5. **Walls and privacy.** Until the seller uploads and the buyer injects, the set exists only on the seller's machine and the seller's chosen folder. The app sends nothing to Pactlab except the AI job payloads when online (document content for classification/OCR under the same data terms as every AI job) and anonymous crash/usage telemetry if the user opts in. The buyer sees the set only after injection.


## Look, motion and the hand-sourced path (Kumar, 2026-11-26)

6. **It has to look genuinely good.** Rinse is the first Pactlab product most sellers will ever touch, and its polish is the brand's proof. Visual bar: the Pactlab identity (navy `#081127`, indigo `#6978ff`, Manrope) executed to the standard of a consumer-grade app — calm, confident, generous spacing, no enterprise-grey. **The flask logo is animated**: the locked B2 flask mark (apps/site/public/brand) gets a motion treatment — the gradient liquid gently moving and **smoke/vapour curling from the flask's mouth** — used on the launch screen and, while a rinse is running, as the working state (the flask is literally at work on your documents), settling to still when the set is clean. Animation is SVG/vector, lightweight, and honours the OS reduced-motion setting. Motion never decorates a state it doesn't describe.
7. **Hand-sourced entries — when the data exists but no file does.** Every gap in the checklist offers two ways to close it: add the file, or **enter the data by hand**. Hand entry opens a structured form for that document type (a vacancy/occupancy schedule, key lease terms, a debt schedule — the form carries the fields that document type is expected to have; a free-form attested note covers the rest), and on save Rinse **generates the file**: a canonical-format document built from the entered values, visually stamped "Hand-sourced — entered by [name, org] on [date]", with the values also stored structured in the manifest. Provenance is first-class: the manifest records `source: hand_entry`, the entering user's verified identity and the timestamp, and the entry stays editable (versioned) until upload. **The integrity rule: hand-sourced closes the completeness gap but is never documentary evidence.** At injection it lands in the pact as a seller **claim** (the packs' claims-register pattern), labelled hand-sourced wherever it is used — a finding or a Deal Critical (T-179) resting on it shows that provenance, so asserted data never silently wears evidence's clothes.

## Checks

- Fixture rinse: a mixed set (scan, docx, xlsx statement, duplicate, corrupt file, one missing expected document) → statements packaged for import, documents converted with page anchors, duplicate/corrupt flagged, gap listed; after the fixture gap is resolved, the set marks ready and the emitted folder + manifest verify against the schema.
- Manifest contract test: a hand-built manifest from the desktop app round-trips through the pact-side sync unchanged.
- Offline test: deterministic checks and conversion complete with the network off; AI steps queue and run on reconnect.

## Acceptance

- A seller-side user installs the app, rinses a messy 20-file set, closes the gaps the checklist names, and uploads the finished folder to OneDrive — the folder + manifest are complete and self-describing.
- A fixture whose scan mis-reads a revenue total in conversion is caught by the audit (original vs converted shown side by side) and cannot be marked ready until resolved; a fixture whose original statement does not foot is marked a source discrepancy and travels as a noted gap.
- A vacancy gap closed by hand entry produces a stamped, canonical file in the uploaded set whose manifest entry reads `source: hand_entry` with the enterer's identity, and which arrives in the pact as a labelled claim, not evidence.
- The buyer connects that folder to a pact and the documents arrive classified, gap-noted and citable to their originals.
- macOS and Windows builds install from the public download page and auto-update (Linux build produced; signing status recorded honestly in the runbook).
