# T-008 — Web sign-in (Auth0)

Status: ready
Needs: T-002
Touches: apps/web/app apps/web/lib apps/web/middleware.ts
Lane: web
Checks: pnpm lint && pnpm typecheck && pnpm test

## Brief

Browser login via Auth0 — end the hand-minted-token era. The API already
verifies Auth0 Bearer JWTs; the web shell currently renders signed-out only
(see apps/web/lib/session.ts).

- Add `@auth0/nextjs-auth0` (v4) to apps/web; wire the Regular Web Application
  credentials from env: AUTH0_DOMAIN, AUTH0_CLIENT_ID, AUTH0_CLIENT_SECRET,
  AUTH0_SECRET (session encryption), APP_BASE_URL, AUTH0_AUDIENCE.
- Login/logout routes; session in an encrypted cookie.
- `middleware.ts`: protect the `(app)` route group — signed-out visits redirect
  to login, signed-in users proceed.
- Organization-aware: the Pactlab API requires `org_id` in the token. After
  login, list the user’s organizations; if exactly one, select it silently; if
  many, offer a picker and persist the choice in the session. Pass
  `organization` as an authorization parameter so access tokens carry `org_id`.
- Server-side API client: every call to the Pactlab API attaches the session’s
  access token as `Bearer`. No token handling in components.
- The shell shows the signed-in user and active organization;
  `getSessionPermissions()` in lib/session.ts returns real permissions (from
  the session / API) instead of the empty stub.
- Document the new env vars in `.env.example` (names and explanations only —
  never values).

## Acceptance

- A signed-out visit to any `(app)` page redirects to the Auth0 login.
- After login (+ org pick when needed), the shell shows the user and org; the
  deals list loads through the session token with no manual steps.
- Logout clears the session and returns to the signed-out view.
- `pnpm lint && pnpm typecheck && pnpm test` green.

## Out of scope

- Enterprise SSO/SAML connections (dashboard config, not code).
- Organization management UI (create org, invite users).
- Machine-to-machine / API-key access (separate concern).
