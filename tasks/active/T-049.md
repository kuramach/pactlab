# T-049 — Tiered context for the agent loop: stop loading the deep context on every task

Status: ready
Needs: none
Touches: CLAUDE.md scripts docs tasks
Lane: agent-loop

- Problem: every loop run loads the full deep context (CLAUDE.md, the whole
  spec, ADRs, PARALLEL_OPS) no matter how small the task is. A one-line fix
  pays the same context cost as an architecture task — wasted tokens, slower
  turns, and the signal in a big prompt gets diluted. Context spend must be
  proportional to the task.
- Task files gain a `Context:` field — `light | standard | deep`. Absent =
  `standard`. Kumar (or whoever writes the task) can always override.
- `scripts/run-task.sh` assembles the run's context by tier:
  - `light`: thin core only — repo map, conventions, the task file itself, and
    the files under `Touches:`. No spec dump, no ADR dump.
  - `standard`: the core plus only the spec sections and ADRs relevant to the
    task's `Lane:`/`Touches:` (a maintained lane → docs mapping, not keyword
    guessing).
  - `deep`: everything, as today — reserved for architecture and
    multi-module work.
- Restructure `CLAUDE.md` into that thin always-loaded core with pointers to
  on-demand docs. Nothing the agent genuinely needs every run may move out of
  the core; everything else is referenced, not inlined (eager @imports of the
  full doc set are the anti-pattern being removed).
- Guardrail: if a run fails CI/tests and the failure is attributable to
  missing context, it retries once at the next tier up and the retry is
  logged. Tiering must never silently starve a task.
- Measure it: each run logs its tier and initial context size (tokens or
  characters) into the task's log file, so the saving is visible, not assumed.
- Acceptance: (1) a `light` docs/task-file-only change runs with ≤25% of the
  initial context of a `deep` run, measured from the logs; (2) a `standard`
  build task completes green with no context-starvation retry; (3)
  `docs/PARALLEL_OPS.md` documents the tiers and the override.
