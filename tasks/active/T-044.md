# T-044 — Breadcrumbs that remember where you came from

Status: ready
Needs: none
Touches: apps/web tasks
Lane: web-ux
Context: standard

- Problem, reported on a live walkthrough: Finances → MRR → "Definitions and
  inputs" → Source Record → open one record. The record page (evidence
  detail, `apps/web/app/(app)/deals/[dealId]/evidence/[evidenceId]/page.tsx`)
  offers only a hardcoded "← Evidence" link, so after reviewing the record
  the user lands on the Evidence browser instead of back on the Finances
  screen they came from. The deal header breadcrumb (Home / My deals / deal)
  is static and does not reflect the in-deal trail either.
- Make detail-page return navigation origin-aware. Links that drill into a
  record from another screen — the Finances/findings "Source Record" links,
  the evidence browser, and any other inbound link to evidence detail —
  carry a return context (origin path including its query string, plus a
  label). The evidence detail page renders its back link and breadcrumb
  from that context when present, falling back to "← Evidence" when absent.
- Validate the return target before using it: internal path, same deal only —
  never an open redirect. A malformed or cross-deal value is ignored and the
  fallback applies.
- Put the mechanism in one shared web helper/component so the next detail
  page gets it for free, instead of another hardcoded back link.
- Acceptance: the reported path round-trips — from Finances (MRR,
  "Definitions and inputs") open a source record, follow the back/breadcrumb,
  and land on the same Finances screen with its state intact. Direct entry
  to a record with no origin still returns to the Evidence browser.
- Tests: web tests for the origin-aware back link (context present, absent,
  and invalid/cross-deal) and for a drill-down link emitting the context.
