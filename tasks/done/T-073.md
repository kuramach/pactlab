# T-073 — Foresight (codename Nostradamus): 5-year trend lines and future value of the target

**Lane:** core
**Context:** deep
**Touches:** domain, db, api, web, ai, packs, spec
**Needs:** none

## Kumar's feature (2026-10-24, his words)

"AI will predict the key trends for the next 5 years like wars, inflation, trade wars, govt posture, stock market swing etc — whatever is key for each of the packs. We will also allow the user to predict the future for 5 years. Then we use voice to ask questions to the AI and it can respond via text or voice. With these trend lines it can predict what will be the value of the acquired business in 5 years."

## Naming

- Product name: **Foresight** ("Pactlab Foresight"). Rationale: the brand line is "AI rigor. Human judgment." — *Nostradamus* reads as prophecy/mysticism and undercuts the rigor story with buyers. **Nostradamus stays as the internal codename** (task titles, code comments) — never user-facing copy.
- Alternates if Kumar overrides: Horizon, Delphi. Until he does, build with Foresight.

## Part 1 — Trend lines (AI baseline, per pack)

- A **trend line** is a structured object, not a paragraph: name, category, 5-year direction and expected magnitude, narrative, confidence, and an **as-of date + model version**. Categories (baseline set): geopolitical conflict, inflation/monetary policy, trade/tariffs, government/regulatory posture, market cycle (equity/credit), plus sector categories each pack adds.
- **Packs declare their key trends.** Extend the pack framework (T-050/T-057): every pack ships a trend definition set — the questions that matter for that industry (hotels: travel demand, rates, labor; multifamily: housing supply, rent growth, rates; fintech: regulation posture, rates; healthcare: reimbursement policy; and so on). The baseline software pact uses the generic macro set. A pack without definitions falls back to the generic set.
- Generation: the AI pipeline (existing model routing — balanced tier to draft, deep-review tier for the projection narrative) produces a deal's trend set on demand and on a refresh cadence. Each trend is stored with provenance (AI-generated vs user-entered — see Part 2), so a trend set is auditable later, never silently current.

## Part 2 — The user's own predictions (scenarios)

- A user can build a **named scenario** on a deal: override any trend's direction/magnitude, add a custom trend of their own ("rates stay above 6% through 2028"), or weight trends differently. The AI baseline is never edited — scenarios layer on top of it, exactly like valuation scenarios layer on the bridge.
- Scenarios are the user's judgment made explicit — and per the product's core rule, every assumption stays visible and editable. Side-by-side compare: AI baseline vs the user's scenario vs a second user scenario.

## Part 3 — What is this business worth in 5 years?

- The projection engine takes the deal's valuation (Sextant: current value, growth/margin assumptions, exit multiple conventions already in the assumption registry) and applies the selected trend set's impacts — revenue growth delta, margin pressure, multiple expansion/compression, discount-rate shift — each impact a named, inspectable assumption, not a hidden multiplier.
- Output is a **5-year value path and range** (year-by-year trajectory to a +5y range), never a single-point "prediction." The UI language is "projected value under these assumptions" everywhere — no prophecy copy.
- A **sensitivity view** ranks which trends move the 5-year value most, so the user sees what the projection actually hinges on.

## Part 4 — Voice Q&A

- The user can **ask questions by voice** about the deal's trends and projection ("What happens to the exit value if rates stay high?") and get the answer in text, or spoken if they toggle voice replies on.
- Integrate, don't rebuild: **Amazon Transcribe** for speech-to-text and **Amazon Polly** for text-to-speech (AWS-native, already our cloud). Answers come from the existing AI pipeline grounded in the deal's trend set, findings, and projection assumptions; an answer must name the trends/assumptions it relies on.
- Every Q&A (question transcript + answer + the scenario it was asked against) is saved to the deal's activity/audit log. Audio is processed for transcription and **discarded by default** — transcripts are what's kept.

## Guardrails

- Projections are scenarios with explicit assumptions — the word "prediction" never appears in user-facing output as a claim of fact; trend lines carry as-of dates and confidence.
- AI-generated trends and user-entered trends are visually and structurally distinct everywhere.
- No fabricated precision: ranges and trajectories, not point values with false decimals.
- Voice is an interface layer over the same grounded Q&A — no separate ungrounded chat brain.

## Acceptance

- For a deal in any pack, a trend set generates with the baseline categories + that pack's sector trends, each carrying direction, confidence, as-of date, and model version; a pack without definitions gets the generic set.
- A user scenario overriding a trend recomputes the projection without touching the AI baseline; baseline and scenario compare side by side.
- The 5-year projection renders as a value path/range with the assumption trail inspectable per impact, and the sensitivity ranking names the top drivers.
- Voice: a spoken question produces a transcript, a grounded text answer citing its trends/assumptions, and (toggle on) a spoken reply; the exchange appears in the deal's audit log and no audio file is retained.
- Spec amended with the Foresight model (trend lines, scenarios, projection, voice Q&A); seed/demo data includes a trend set + one user scenario for a demo pact.
