## Why
Kumar (2026-11-26): *"Yes slack and teams for sure."*
- PE and corp-dev teams work in Slack or Microsoft Teams all day, and both carry bot messages at no per-message cost.
- T-180 adds the profile's contact channels: email, Telegram and WhatsApp. This task adds Slack and Teams to the same profile and the same `user_contact_channels` table.

## What to build
### 1. Organization install (an admin, once)
- **Settings → Connected apps → Slack / Microsoft Teams.** An organization admin installs Pactlab into the company's workspace or tenant.
- **Slack:** OAuth v2 app install, least-privilege bot scopes only (e.g. `chat:write`, `im:write`, `users:read`, `users:read.email`).
  - The bot token is kept as a revocable credential reference, never in a row or a log.
  - Uninstall and token revocation (the `app_uninstalled` and `tokens_revoked` events) disable the channel straight away.
- **Teams:**
  - a Teams app (manifest) with a bot registered through Azure Bot Service and the Bot Framework;
  - the admin deploys it to the tenant;
  - proactive messages need the conversation reference captured when the app is installed for a user, so store that per person.
  - Inbound bot calls are verified (Bot Framework JWT validation).
- **Verify first:** check every scope, endpoint, event and manifest field against Slack's API docs and Microsoft's Teams and Bot Framework docs before writing code. Invent nothing.

### 2. Per-person link (on "Your profile", from T-180)
- **Connect Slack / Connect Teams:**
  - match the person to their Slack or Teams user by their **verified** Pactlab email (T-180);
  - send a one-time confirmation message in Slack or Teams ("Is this you? Confirm"), and link only once they confirm.
- **Disconnect:** from Pactlab, or by an action in the app's home tab.
- **No workspace install:** the card says "Ask your admin to connect Slack (or Teams) for your organization", with nothing to click.

### 3. Sending
- **The message:** a direct message from the Pactlab bot, never posted to a channel.
- **Content-free, the same rule as T-146:**
  - "Pactlab: an action is waiting for you on a pact.", plus an **Open Pactlab** button that needs sign-in;
  - no pact name, party, amount or document text, because workspaces are shared, logged and searchable by the customer's admins;
  - the rule is enforced in code and in tests.
- **Respect platform limits:** Slack rate limits, and Teams throttling with retry-after.
- **Connector seam:** both platforms sit behind it, with fixture adapters, and are off by default. The runbook lists Kumar's one-time steps as a short checklist:
  - creating the Slack app;
  - registering the Azure bot;
  - Teams app publishing or sideloading.

## Rules
- Workspace and tenant ids, user ids and tokens are personal or credential data: never sent to models, logged or put in fixtures. Tokens go through the credential-reference store.
- RLS: a person sees only their own links; an admin sees which members are linked, not their user ids.
- Audited: install, uninstall, link, unlink, and every send's delivery outcome, with no content.
- The ADR from T-180 is extended (or a new ADR filed) for the Slack and Teams choices.

## Acceptance
- With the fixtures, an admin installs Slack, a member links by verified email and confirms, a test DM arrives, and the member disconnects; the same for Teams.
- Uninstall or token revocation stops sends immediately.
- Tests prove no pact content reaches a Slack or Teams payload.
- A member of another organization can't link to this organization's install (RLS and API deny tests).
