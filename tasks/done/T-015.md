# T-015 — Per-organization sign-in: Auth0 or emailed one-time code

Status: done
Needs: T-010, T-014
Touches: packages/db packages/config apps/api/src apps/web docs/adr docs/runbooks/sso-setup.md .env.example tasks

Checks: pnpm lint && pnpm typecheck && pnpm test && pnpm test:fixtures && pnpm test:integration

## Brief

Organizations choose Auth0 or a Pactlab-native emailed 6-digit code
(decided with the founder; ADR `docs/adr/0001-per-organization-sign-in.md`).
Plan: `/v1/auth/email/{start,verify}`, `/v1/auth/session/organization`,
`/v1/auth/logout`; issuer-aware principal resolution; SECURITY DEFINER
login functions owned by `pactlab_auth`; `/login` chooser in the web app;
seeded email-code organization "Charlie Advisory".

## Deviation from the approved plan

Auth0 configuration became optional per deployment (all-or-nothing), so a
deployment — or a local run — can offer email-code sign-in without Auth0.
Missing Auth0 config disables Auth0 sign-in; it never opens it.

## Follow-ups

- SES (or other) email adapter for deployed environments.
- Org-admin UI to choose the method and invite email-code users.
- Contract migration: rename `users.auth0_subject` → `identity_subject`.
