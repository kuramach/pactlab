## Kumar's decision (2026-11-05)

"Until all the packs are developed, I just want to test on dev and push to live. This way I can idle or stop qa and stage to save costs. We don't have any customers, so that is OK to speed up live push for now."

Interim promotion path until the packs are complete and customers arrive: **branch → dev → merge → main → dev → live.** Qa and stage are parked, not deleted: they stay deployable by manual dispatch if ever needed, but nothing in the normal flow waits on them.

## Current state (verified 2026-11-05)

- deploy.yml dispatch options are `[dev, qa, stage]` — **live is not deployable at all yet**; ADR 0019 already names it as the final step ("live, later").
- GitHub Environments that exist: dev, qa, stage (plus site, site-diff). **No `live` environment exists.**
- CDK config has `prod.ts`; the deploy model calls this environment `live`. Reconcile the naming where they meet (dispatch input, stack name, CDK context keys) and make the mapping explicit in one place — do not rename files for cosmetics.
- Qa/stage already have idle-pause machinery (idle-pause + wake). Parking therefore has two levels: idle-pause (compute/DB sleep; NAT + ALB still bill, roughly $50/mo/env) and full stop (teardown; saves that too, costs a re-provision later).
