# T-174c — Generated documents in the pact's working language, with an embedded Japanese font

Engine: claude
Model: opus
Lane: platform
Context: deep
Touches: apps/api packages/ai docs tasks
Needs: T-174b
Checks: pnpm lint && pnpm typecheck && pnpm test && pnpm test:integration && pnpm test:fixtures && pnpm test:e2e

## Why
T-174b stored the pact's working language (`deals.working_language`) and the run's language, but generated documents are still English-only and the PDF fonts (Manrope, Inter, Source Serif) carry no Japanese glyphs, so Japanese text prints as "?".

## Build
1. **Font (approved, Kumar 2026-11-28):** Noto Sans JP under the SIL Open Font License 1.1. Verify the licence from the official source (Google Fonts / notofonts), pin the version, carry the licence in the notices, subset on embed (`@pdf-lib/fontkit`).
2. **Catalogs:** typed report, IC pack, term sheet and LOI catalogs per language (en source; de, fr, ja), `satisfies` so a gap fails typecheck (ADR 0064 convention).
3. **Rendering:** each document in the pact's working language with T-170's formatter in that locale; the header logo, footer ("Powered by Pactlab") and sender present in every language.
4. **Rules:** translated drafts labelled with their source language; executed (signed, countersigned) documents never translated; stored LOIs and term sheets frozen by digest stay as generated.
5. **Tests:** de and ja documents with EUR and JPY pacts (extract the PDF text): German throughout with euros de-DE; Japanese with yen and no "?" replacement glyphs.
6. **AI:** briefs and triage verdicts a person reads pass the reader's language (as Q&A does since T-174b).

## Acceptance
- A report for a German EUR pact is German throughout, euros in de-DE; a Japanese JPY pact's report renders Japanese with an embedded font and yen formatting.
