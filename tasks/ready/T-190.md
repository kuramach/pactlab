## Why (Kumar's decisions, 2026-11-27)
- The repo goes **private**; at the November 2026 build pace, GitHub-hosted CI on a private repo would cost ~$300/month (measured: 497 ci.yml runs in 8 days, ~21 billable minutes each). A self-hosted runner makes CI minutes $0.
- **dev, qa and stage move to a home Linux box**; only **live** stays on AWS. The parked AWS environments bill ~$50/month each doing nothing and several times that awake. The home envs still call a thin layer of AWS services (Bedrock, SES, S3) at dev-scale cost.
- The box: **GMKtec K8 Plus** — Ryzen 7 8845HS (8C/16T), 32GB DDR5 (2 SODIMM slots, upgradable to 64/96GB later), 1TB PCIe 4.0 NVMe plus a second M.2 slot, **dual Intel 2.5GbE**, Wake-on-LAN and Auto Power On. Benchmark price $909.99 (Newegg, Black Friday 2026); Kumar purchases it himself. It runs headless — no monitor after a one-time setup on any display.
- Order of operations is a security rule: **the repo flips private BEFORE any self-hosted runner is attached** (GitHub warns never to run self-hosted runners on public repos — anyone can open a PR and execute code on the machine). The private flip itself is Kumar's settings click; the runbook carries the checklist.

## Part 1 — Box provisioning (runbook + scripts)
- Ubuntu Server LTS, Docker, headless operation: SSH key access, Tailscale (Kumar already runs it), optional Cockpit for a browser dashboard.
- Two separate OS users: `runner` (CI only) and `envs` (environment stacks). The box holds **no production AWS credentials, ever**, and opens **no inbound ports** — the runner polls GitHub outbound; env access is via the Part 3 tunnel, also outbound-only.
- Verify and record in the runbook: Wake-on-LAN works, Auto Power On after a power cut works, the box returns to full service unattended after a reboot.
- Provisioning scripted under `scripts/home-server/` so the box can be rebuilt from the runbook alone.

## Part 2 — Self-hosted CI
- Register **3 runner instances** on the box under the `runner` user, labelled `pactlab-home`, after the private flip is confirmed.
- Move the heavy workflows to the self-hosted runners: `ci.yml`, `e2e-full.yml`, `integration-live.yml` (`runs-on: [self-hosted, pactlab-home]`). Install the toolchain the jobs expect (Node/pnpm per repo config, Playwright browsers and their system deps).
- **Keep on GitHub-hosted runners:** `deploy.yml`, `site.yml`, `release.yml` and the env-power workflows — rare, and they touch AWS; the home box never holds the credentials they use.
- Prove it: a full CI run green on the self-hosted runners, then a week of normal loop traffic with no queueing collapse (3 instances against ~21 job-minutes per run at peak pace).

## Part 3 — dev/qa/stage at home
- One container stack per environment under the `envs` user, reusing the local-dev topology: web/api/worker + Postgres + Redis per env, per-env seed via the existing demo-org machinery. RDS → local Postgres, ElastiCache → local Redis, ALB → a small reverse proxy (Caddy or nginx) on the box.
- **Thin AWS layer stays:** Bedrock (called through the **stage** account, where it is verified working — this also unblocks dev AI, which the dev account's missing Bedrock enablement has blocked), SES for env email, S3 for env documents. Credentials are scoped IAM keys for the **dev/stage accounts only**, stored in a secrets file on the box (never in the repo), injected into the env stacks only — the `runner` user cannot read them.
- **Outside access for the tester: Cloudflare Tunnel + Cloudflare Access.** The tunnel daemon dials out; dev./qa./stage.pactlab.ai resolve at Cloudflare. Access policies: the tester (allowlisted email, one-time code or Google sign-in at Cloudflare's edge) reaches **qa and stage only**; **dev is Kumar-only**. No port forwarding, home IP never exposed, HTTPS certificates automatic. DNS cutover is part of this part.
- **AWS side:** once the home envs soak, idle-pause the AWS dev/qa/stage stacks. **Destroying them is a separate step gated on Kumar's explicit go** — this task pauses and reports the projected saving; it does not destroy.
- **T-157 follow-through:** the dev/qa/stage log triage built to run inside AWS is reworked into a scheduled job on the box producing the same digest surfaces (email + GitHub), or retired for those envs with the reason recorded in the runbook. Live triage (T-150) is untouched.

## Rules
- Live is never in scope: no change to the prod account, the live stack, or the live deploy path.
- Secrets never enter the repo — the runbook names where each secret lives, never its value.
- Every workflow left on GitHub-hosted runners is listed in the runbook with its reason.
- The repo's CLAUDE.md testing principles hold on the self-hosted runners unchanged (no live model calls in CI, per-test isolation).

- Box reboot test: power-cycle → runners and all three env stacks return unattended.
- AWS cost check after idle-pause shows the dev/qa/stage environment spend at ~zero beyond the thin services (Bedrock/SES/S3 usage), with the before/after figures recorded in the runbook.
