Engine: claude

**Lane:** platform
**Context:** standard
**Touches:** apps/api (oauth, auth, deals, documents, findings, common), packages/db, packages/contracts, apps/web (device, oauth, settings, developers, navigation), docs/adr/0024

## Kumar's request (2026-11-16)

"Once we login, we need to have two useful menus, one will Be the api set and details and how to connect via ur own personal token etc and second is have the details on how to use the mcp via Claude."

Answers:
- **Method:** "It does not have to be tokens. It can be any method that is secure and per login since we can track it by user".
- **Who:** members; admins can turn it off.
- **Docs:** a generated reference plus a guide.

## Delivery

- **PR 1 (this one): API access.**
  - The REST API is a second OAuth resource (`api:read`, `api:write`).
  - Scripts sign in with the device flow at `/device`.
  - `@ApiAccess()` is the allowlist.
  - Organization admins get an API access switch and see and remove grants in Settings.
  - ADR 0024 addendum.
- **PR 2: the menus.**
  - The OpenAPI spec generated from the `@ApiAccess()` routes' Zod schemas, at `/v1/openapi.json`.
  - A Developers sidebar group: API (guide and reference) and Use with Claude (MCP guide, with live state).
  - A wider first catalog of routes.
