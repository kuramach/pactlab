# T-154 — Delete an import and re-import: audit-safe semantics

Engine: claude
Model: opus
Lane: core
Context: deep
Touches: packages/domain packages/db apps/api apps/web docs
Needs: none

## Why

Imports land real data (P&L lines, rent rolls, extracted fields) that QoE and valuation now read (PR #254, T-149). Users will import the wrong file, or the wrong version, and need to remove it and re-import. Kumar's question (2026-11-24, immediate set): how does deleting an import work with the audit trail? This task designs and builds the answer: nothing ever silently disappears from Pactlab — an import can be withdrawn, but the record of it, and of everything it fed, stays explainable.

## Design (the semantics to implement)

1. **No hard delete.** Deleting an import is a state change, not an erasure: the import is marked withdrawn with actor, timestamp and a required short reason. The import record, its file reference, its mapping and guidance (T-152), and its row counts remain readable in an audit/history view to users with manage rights.
2. **Derived data is voided, not vanished.** Everything the import produced (imported rows, P&L lines, extracted values) is marked void and excluded from every read path (QoE, valuation, findings, exports) from the moment of withdrawal. The voided records remain in storage with a pointer to the withdrawal, so any number a user saw earlier can still be explained.
3. **Downstream findings are flagged, never silently changed.** If findings or a valuation run already consumed the import's data, those artefacts are NOT rewritten. Instead they gain a visible "source withdrawn" staleness flag wherever they are shown, and the pact's audit log records which artefacts were affected. Re-running QoE/valuation after a re-import produces fresh artefacts; the flagged ones keep their history.
4. **Re-import is a new import with a lineage.** Re-importing creates a new import record linked to the withdrawn one (supersedes / superseded-by), reusing the saved guidance by default (T-152). The chain is visible in the import history: v1 withdrawn (reason) → v2 active.
5. **Audit log entries** for: import created, import withdrawn (with reason), artefacts flagged, re-import created. All in the existing audit machinery and vocabulary — no parallel log.

## Build

- The state model and transitions above (import status, void markers on derived rows, staleness flag on consuming artefacts), with the read-path exclusions enforced in the domain layer and covered by contract tests so a future read path can't quietly include voided data.
- API + UI: a Withdraw action on the import detail (manage rights only) with a confirmation that states plainly what will happen — derived data stops counting, citing findings get flagged, the record stays in history — plus the reason field. Import history view showing the lineage chain and withdrawal reasons.
- An ADR recording the semantics and the reasoning (auditability beats tidiness), and a runbook note for support: "a customer asks where their numbers went."

## Guardrails

- Confidentiality unchanged: withdrawal never widens who can see the import or its history.
- Valuation integrity: the bridge and confirmed-value ledger never consume voided data, and a valuation run's inputs remain reproducible after a withdrawal (the run keeps what it used; the flag says a source was later withdrawn).
- No bulk/purge tooling and no time-based auto-deletion in this task.

## Checks

- Tests: withdrawal excludes derived rows from QoE/valuation reads; citing findings show the staleness flag; audit entries exist for every transition; re-import lineage links both ways; a user without manage rights cannot withdraw.
- End-to-end: import a P&L → run QoE → withdraw the import → QoE no longer reads it and the earlier run is flagged → re-import → fresh run reads the new data.

## Acceptance

- A user can withdraw a wrong import in under a minute, with a reason, and trust that (a) its numbers stop counting everywhere, (b) anything built on them is visibly flagged, and (c) the full story remains in the audit history.
