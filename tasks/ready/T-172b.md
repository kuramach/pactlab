# T-172b — Store the reader's language on the person and an organization default; German e2e on the pilot surface

Engine: claude
Model: opus
Lane: web
Context: standard
Touches: packages/db apps/api packages/contracts apps/web apps/e2e docs tasks
Needs: T-172
Checks: pnpm lint && pnpm typecheck && pnpm test && pnpm test:integration && pnpm test:e2e

## Why
T-172 resolves the locale as the person over the organization over English (ADR 0064), but `packages/db` and `apps/e2e` were outside its paths: the person's choice lives only on the device (`pactlab_locale` cookie) and no organization default is stored. The German pilot journey has no browser test.

## Build
1. **Schema (expand only, plan mode first):** `users.locale` and `organizations.default_locale`, nullable, CHECKed to `en | de | fr | ja`. Writes go through the same SECURITY DEFINER path as other user-profile writes; owners and admins set the organization default (RLS).
2. **API:** `GET /v1/me` returns `user.locale` and each organization's `defaultLocale`; `PUT /v1/me/locale` and `PUT /v1/organization/locale` (owners/admins), schemas in `packages/contracts`, audited (`user.locale_set`, `organization.locale_set`).
3. **Web:** `getI18n()` reads the person's stored locale, else the cookie (kept for signed-out pages), else the organization default; Settings → Language saves to the API and sets the cookie; owners and admins get the organization default beside it.
4. **E2E (`apps/e2e`):** a German journey on the pilot surface: set German in Settings, the pact home and Findings render in German (role-based locators, German labels), back to English instantly; burned in before it gates.

## Acceptance
- A person's language follows them across devices; an organization default applies to members who have not chosen; the e2e German spec is green and the English suite unchanged.
