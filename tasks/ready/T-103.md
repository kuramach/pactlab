# T-103 — Managed malware scanner for live
Engine: claude

**Lane:** infra
**Context:** standard
**Touches:** apps/api/src/documents/upload-policy.ts (scanner adapter), infra/cdk (scanner wiring), packages/config/src/env.ts, docs
**Needs:** Kumar's choice between the two options below (one is a paid AWS service).

## Why

Live launched (2026-11-05) with the signature scanner as an **accepted risk**: Kumar postponed the managed scanner to get live up sooner. Every upload to live currently gets only the signature (EICAR-class) check. `packages/config/src/env.ts` allows the signature scanner in `production` until this ships.

## Options (decide first)

1. **ClamAV container beside the API.** Open-source and free; scans each upload synchronously, exactly where the `MalwareScanner` port plugs in today. Signatures update with `freshclam` over the NAT gateway. Costs about $15–30 a month in extra task memory.
2. **Amazon GuardDuty Malware Protection for S3.** Managed and paid per GB scanned (cents at pilot volumes). It scans *after* the object lands in S3, so uploads need a quarantine-then-release flow: store under a quarantine prefix, wait for the scan tag, then release or reject.

## Done when

- **Scanner:** live runs a managed scanner, and `production` is removed from `SIGNATURE_SCANNER_ENVS`.
- **Tests:** a clean file passes; the EICAR test file is rejected; an unavailable scanner fails closed (503, nothing stored).
- **Records:** the ADR 0019 addendum and the runbook's "Not yet" list are updated.
