# T-116 — Demo share links redirect to the internal VPC host after sign-in

Model: sonnet
Engine: claude
**Lane:** core (web / auth-adjacent)
**Context:** standard
**Touches:** apps/web (demo link route; any route handler with the same pattern)
**Needs:** nothing

## Symptom (live, 2026-11-10)

Opening a shared-demo link signs the visitor in, then redirects the browser to
`https://ip-10-0-8-151.us-east-2.compute.internal:3000/deals` — the web task's
internal VPC address. No browser outside the VPC can resolve that host
("can't find the server"), so shared demo links appear broken even though the
sign-in itself worked.

## Root cause

`apps/web/app/demo/[token]/route.ts` builds both redirects from the request URL:

```ts
return NextResponse.redirect(new URL('/demo/ended', request.url));
return NextResponse.redirect(new URL('/deals', request.url));
```

In the deployed web service, `request.url`'s origin is the internal task
address, not the public `https://app.pactlab.ai`, so the redirect leaves the
public internet entirely.

## Fix

- Build these redirects from the web app's configured public origin (the same
  source other absolute URLs in apps/web are minted from — find it; do not add
  a new env var if an existing one serves). Never derive a browser-facing
  redirect target from `request.url`'s origin.
- Grep apps/web for the same pattern (`new URL(` with `request.url`,
  `NextResponse.redirect` built from the request) and fix every instance, not
  just the demo route.

## Acceptance

- Opening a valid demo link on app.pactlab.ai lands on
  `https://app.pactlab.ai/deals`, signed in as the demo buyer/seller.
- An ended or unknown token lands on `https://app.pactlab.ai/demo/ended`.
- A test asserts the redirect `Location` origin equals the configured public
  web origin (and would fail on an internal/`request.url`-derived origin).
- No remaining `request.url`-origin redirects in apps/web route handlers.
