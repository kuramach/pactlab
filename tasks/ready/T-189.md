# T-189 — Hibernate dev, qa and stage: near-zero cost when unused, rebuilt on demand (plan first)

Engine: claude
Model: opus
Lane: platform
Context: deep
Touches: infra/cdk .github/workflows scripts docs tasks
Needs: none
Checks: pnpm lint && pnpm typecheck && pnpm --filter ./infra/cdk test

## Why
Kumar (2026-11-27): *"stage is still using hosting $. can we minimize it to zero?"* He chose **hibernate**, for **dev, qa and stage**.

**Today** (`infra/cdk/lib/idle-pause.ts`, ADR 0019): after 60 idle minutes the services scale to zero and the database stops, but these keep billing around the clock:
- **Redis:** stage has 2 × `cache.t4g.small`; dev and qa share 1 × `cache.t4g.micro`.
- **The load balancer** and its public IPv4 addresses.
- **The NAT instance** and its Elastic IP.
- **Database storage and backups.** Stage keeps 50 GiB Multi-AZ with 14 days of backups.
- Secrets, KMS keys, logs and the DNS zone.

A stopped RDS instance also restarts itself after 7 days. Paused stage is roughly $90–110 a month, and dev with qa less.

## Plan first (CLAUDE.md: plan mode before infrastructure changes)
**The first run writes the plan as an ADR** (amending ADR 0019) **and stops**; the runner pushes it without a PR. Kumar approves, and the next run builds it.

The plan must cover:
- what is torn down and what stays;
- how data survives;
- wake time;
- the cost while hibernated, itemized from AWS's published us-east-2 prices, with each price checked against the official pricing pages;
- what breaks: DNS, certificates, OAuth redirect URIs, SES identity, webhooks, log triage;
- how each of those is handled.

## Build (after approval)
- **Hibernate,** a GitHub Actions workflow per environment, dispatched by Kumar, or automatically after N idle days (N proposed in the ADR):
  1. snapshot the database, then delete the instance;
  2. delete the compute, the load balancer, the NAT, Redis, and the VPC if nothing else needs it;
  3. **keep** the evidence and document buckets (retained), the database snapshot, secrets, KMS keys, the Route 53 zone, ACM certificates if they can be kept, the SES identity, the audit archive, and the log groups (with short retention).
  - **dev and qa share one base** (network, NAT, load balancer, Redis). It hibernates only when both are hibernated.
- **Wake:** a workflow that restores the database from the latest snapshot and redeploys the stacks.
  - The site shows "This environment is asleep; it takes about 30–40 minutes to wake", with a button that dispatches the workflow, extending today's wake page and `wake.yml`.
  - Data and DNS names come back unchanged.
- **Cheaper while awake:**
  - stage's database becomes single-AZ and smaller, a size the ADR proposes and justifies;
  - stage's Redis becomes one node;
  - backups drop to 3 days in stage, dev and qa.
  - **Live is untouched.**
- **Guardrails:**
  - The workflows refuse `live`.
  - `protectedState` resources are never deleted without a final snapshot.
  - A hibernate whose snapshot fails stops before deleting anything.
  - Each run writes a summary of what was deleted, what was kept, and the snapshot id.
- **Hosting cost page:** shows each environment's state (awake, paused, hibernated) and the cost while hibernated.
- **Runbook:** `docs/runbooks/hibernate.md`, with Kumar's one-line commands (`gh workflow run …` wrapped in `scripts/env-hibernate.sh` and `scripts/env-wake.sh`).

## Acceptance
- CDK tests prove the hibernated shape: the workflows create no live resources and refuse live.
- A dry run (`--dry-run`) lists exactly what would be deleted and kept, per environment.
- The runbook states the measured or estimated cost while hibernated per environment, with sources.
- Agents never run the workflows or touch AWS. Kumar runs the first real hibernate and wake, and the runbook gives the steps.
