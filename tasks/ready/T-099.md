# T-099 — One-drop intake for every pact: recognise structured exports by their columns and import them, no AI needed
Engine: claude

**Lane:** core
**Context:** standard
**Touches:** packages/domain (imports, intake), apps/api (documents, imports), apps/web (documents uploader, sources), apps/e2e, docs (ADR 0016 addendum)
**Needs:** none. Builds on T-098 (intake) and the import pipeline (ADR 0004).

## Kumar's ask (2026-10-29)

Testing a multifamily pact: "So for multi-family we can't import all documents as a zip?" Then: "So this should be a task for all the pacts. Since it is a universal need."

T-098's promise was: when a file is straightforward, Pactlab digests it; when it is unsure, it asks. Today a zip of a pack's data room falls short of that in two ways:

1. **Sorting needs the model.** A CSV or Excel export is filed only by the AI classifier. When AI is unavailable (e.g. an expired local AWS sign-in), every file stays unsorted, even though a template export is identifiable from its header row alone.
2. **A filed export is not imported.** A CSV filed as a rent roll says "Its rows are imported on Sources." The user then re-uploads, maps and imports each file one at a time on Sources. The copy that arrived with the zip is only a document; its rows never reach evidence or the pack's checks.

The goal: **one drop (a zip, several files or a connected data room), then run the checks.** This applies to every pact and every pack: billing, the balance sheet, and every pack's import targets (multifamily rent roll, T-12, delinquency and inspections; hotels, hospitals, healthcare, fintech, pharma, telecom, services, venture, regulatory footprint and package, and so on).

## Part 1 — Recognise exports by their columns (deterministic, before any AI)

- For every CSV, and every Excel sheet read the way `readWorkbookSheets` reads it, compare the header row with each import target **the pact's pack offers** (`importableTargets(pack)` in `imports.service.ts`), reusing `suggestFields` (`packages/domain/src/imports/suggest.ts`).
- Three outcomes, each with the evidence shown (columns matched and required fields covered):
  - **EXACT**: every required field maps, with no ambiguity, and the best target clearly beats the next. The file is filed as that target, with category source `RULE`, and the AI is never called.
  - **LIKELY**: required fields map, but with a renamed or ambiguous column, or two targets are close. The file is filed as a proposal and the person confirms it.
  - **NONE**: falls through to the AI classifier as today. With AI off, it lands in "Pactlab needs you".
- The billing standard template and Stripe-shaped exports go through the same matcher.
- Matching is versioned code with unit tests per target. There are no model calls and no guessing between two equal matches.

## Part 2 — Import what is recognised, from the file that arrived

- An **EXACT** match imports automatically. It runs the normal upload import (`sourceUploads` → `runUploadImport`) from the stored document's bytes, with the suggested mapping and check-every-row. The original is hash-checked first.
- Rows with issues are reported exactly as on Sources. A failed import leaves the file filed and says why.
- A **LIKELY** match gets **Import** on its row. It opens the existing mapping editor pre-filled; the person checks it and imports.
- **Idempotent.** The same file (same sha256 for the same target in the pact) never imports twice: re-dropping the zip, re-syncing a data room or answering the question again adds nothing. Changed content for a known record follows the engine's normal SUPERSEDES versioning.
- **Visibility follows the document.** Files the seller's side uploads (SHARED) import into the SHARED connection; buyer-side files go to BUYER_ONLY. Counterparty boundaries stay as they are (ADR 0015/0016).
- **Traceable and audited.** Every import is linked to its document and records `intake.imported` (target, document, sync run, rows). The Sources page lists it like any other upload, marked "from intake", and each evidence row traces back to the document.
- Once a pack's targets are imported, the pack's checks run as they do after a Sources import. The row says what happened, e.g. "Rent roll: 96 rows imported; multifamily checks ran".

## Part 3 — The drop, end to end

- **Uploader.** Each row's status covers the whole chain: unpacked → recognised (rule or AI) → imported / needs you / filed. One summary line at the end, e.g. "11 files: 5 imported (2,491 rows), 2 contracts extracted, 1 needs you".
- **Data rooms.** Data-room sync (T-098 document sources) takes the same path, so a connected data room with template exports imports them without a manual step.
- **Checklist.** Missing-inputs entries tick off when the import lands, not just when a file is filed.
- **Demo data.** Each pack README in `pactlab-demo-data` gains a "Fastest path" section: download the folder, zip it, drop it on Documents, run the checks. The step-by-step path stays as the fallback. A test in the demo-data generator asserts every pack's CSVs are EXACT matches for their targets.

## Guardrails

- The rule decides only when it is certain. Anything less is a proposal for a person or a question for the AI, never a guess.
- Nothing is imported silently. Every import is visible on the file's row and on Sources, audited, and traceable from evidence back to the document.
- AI never sees file contents it would not see today. The rule path needs no model at all, and people data (`people` categories) keeps its AI exclusion.
- The legal original stays byte-for-byte; imports read it and never rewrite it.
- No new import targets in this task. It routes into the existing ones.

## Acceptance

- **Every pack's demo folder** (every pack in `pactlab-demo-data`, SaaS included), zipped and dropped on Documents with **AI switched off**: every CSV is recognised EXACT and imported with the same row counts the README states. The pack's checks then produce the README's planted findings. Covered by API tests per pack, plus one e2e (multifamily).
- **A LIKELY file** (a renamed column) shows Import with a pre-filled mapping; nothing imports until the person confirms.
- **An unrecognisable CSV** goes to the AI, or to "Pactlab needs you" when AI is off.
- **Re-dropping the same zip** imports nothing new and says so.
- **Seller uploads** import as SHARED and stay invisible to other bidders and to buyer-only analysis, under existing RLS. Tests cover both the allowed and the denied paths.
- **Case 1** (`demo-data/cases/case-01-grocery`): dropping `sites.csv` and `remedy-package.csv` lands the regulatory footprint and package.
