# T-010 — Web sign-in (Auth0)

Status: ready
Needs: T-009
Touches: apps/web .env.example pnpm-lock.yaml packages/config
Lane: web
Checks: pnpm lint && pnpm typecheck && pnpm test

## Brief

Browser login via Auth0 — end the hand-minted-token era. Supersedes T-008:
that brief was unimplementable (see tasks/blocked/T-008.md) — it required
listing organizations via the Management API (ruled out), matched middleware
on a route group that never appears in URLs, and understated its file scope.

- Add the Auth0 Next.js SDK to apps/web. Use the current stable major;
  verify against the installed Next.js version (16.x) and follow the SDK’s
  actual API — do not pin a version from memory.
- Request interception: verify the installed Next.js version’s convention
  (on Next 16+ this is `proxy.ts`, not `middleware.ts` — confirm, don’t
  assume). Protect the authenticated app paths by matching real URL paths
  (route groups like `(app)` never appear in URLs): signed-out visits redirect
  to login.
- Login/logout routes; session in an encrypted cookie.
- Organization flow without the Management API: after login the token may lack
  `org_id`. Call `GET /v1/me` (T-009) with it. If exactly one organization,
  re-authorize with `organization=<id>` silently. If several, show a picker,
  persist the choice in the session, then re-authorize with it. Tokens used
  for API calls always carry `org_id`.
- Server-side API client: every Pactlab API call attaches the session’s
  access token as `Bearer`. No token handling in components.
- The shell shows the signed-in user and active organization;
  `getSessionPermissions()` in lib/session.ts returns the permissions from
  `GET /v1/me` instead of the empty stub.
- Validate new server env vars at startup via `packages/config`
  (AUTH0_DOMAIN, AUTH0_CLIENT_ID, AUTH0_CLIENT_SECRET, AUTH0_SECRET,
  APP_BASE_URL, AUTH0_AUDIENCE); document names in `.env.example` (never values).

## Acceptance

- A signed-out visit to an app page redirects to the Auth0 login.
- A single-org user proceeds with no extra clicks; a multi-org user gets a
  picker; both end with org_id-bearing tokens.
- The deals list loads through the session token with no manual steps.
- Logout clears the session and returns to the signed-out view.
- `pnpm lint && pnpm typecheck && pnpm test` green.

## Out of scope

- Enterprise SSO/SAML connections (dashboard config, not code).
- Organization management UI (create org, invite members).
- Machine-to-machine / API-key access (separate concern).
