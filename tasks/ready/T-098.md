# T-098 — AI document intake: connect the data room (or drop the files), AI sorts and digests, asks only when unsure

**Lane:** core
**Context:** deep
**Touches:** domain (packs, imports), db, contracts, api (documents, imports, connections), worker, ai (prompts), connectors (vdr, storage), web (documents, connections, overview), e2e, scripts/demo-data, docs/adr
**Needs:** none

## Why (Kumar, 2026-10-28)

Input is the slowest part of a pact. Users shouldn't have to know which file
goes where, or label each one "balance sheet", "income statement", "lease".
The AI reads each file and works out what it is. If the file is
straightforward, the AI digests it as that. Only when it's confused does it
ask a person. It also says plainly what's **missing**.

## Product decisions (Kumar, 2026-10-28)

- **Pactlab is not a data room.** It integrates with the data room or file
  store the deal already uses: a VDR, Google Drive, OneDrive/SharePoint or
  similar. Pactlab reads from it. It doesn't replace it, host the room, or
  manage access to it.
- **No data room (small pacts):** the user imports everything once, as many
  files or one zip, and the **same intake process** applies.
- **AI decides the category when it's clear; a person decides when it isn't.**
  No per-file human labelling. Record this in an ADR (0016), including how it
  sits with CLAUDE.md rule 2 (see Guardrails).

## 1. Two ways in, one intake

- **Connected source.** Extend the existing VDR connector
  (`packages/connectors/src/vdr`, metadata-only index + secure upload
  pipeline for bytes) into a **document-source** adapter family with the same
  interface: VDR, Google Drive, OneDrive/SharePoint, and the others the
  interface can absorb (Box, Dropbox). Fixture adapter first; live adapters
  only against each provider's verified, documented API (no invented
  scopes or endpoints). Each provider's read-only scope is listed in the ADR.
  The user picks a room or folder. Pactlab indexes it, pulls each file
  through the existing upload pipeline (scan, page extraction, retention),
  and **re-syncs**: new or changed files go through intake. A file removed at
  the source is marked removed, never silently dropped from lineage.
- **Bulk import.** Many files, or **.zip** archives unpacked server-side
  (folder paths kept as a hint, nested zips one level deep, `__MACOSX` /
  `.DS_Store` / `Thumbs.db` skipped, uncompressed-size and file-count caps
  against zip bombs). Every file gets the same scan and limits as a direct
  upload. A rejected file is listed with its reason.
- Both feed the same intake queue and reuse T-094 B1–B3's per-file states.
  No parallel pipeline.

## 2. AI reads, classifies, digests

- Each file gets a **category** from a pack-aware taxonomy (Balance sheet,
  Income statement, Cash flow, Rent roll, T12, CAM reconciliation, Customer
  contract, Lease, Loan agreement, Cap table, Org chart, Policy, …). Each
  category maps either to an **import target** (structured data → existing
  `IMPORT_TARGETS` mapping, e.g. rent roll → `MULTIFAMILY_RENT_ROLL`; balance
  sheet → T-094 B9's debt and cash reader) or to **document extraction**
  (read for findings). The folder path and file name are hints. The AI
  reads the content.
- **Clear → digested.** Above a stated, per-category confidence bar, the
  file is filed and routed with no human step. Structured files go into the
  import mapping with the suggested mapping applied; documents go to
  extraction.
- **Unclear → asks.** Below the bar, ambiguous between categories, a mapping
  it can't resolve, or contradicting another file (two different balance
  sheets for the same period): the file goes to a short **"Pactlab needs
  you"** list with its best guess and the specific question. One click to
  answer.
- Every classification shows its category, confidence and reason ("sheet
  headers: Unit, Tenant, Rent, Lease end"), and can be corrected at any time.
  A correction re-routes the file and marks downstream results stale. The
  confidence bar is tuned against the demo-data scenarios and recorded
  with the prompt version.
- Duplicates (same hash, or same content in another format, e.g. PDF and
  XLSX of one statement) are spotted and shown as one.

## 3. Tag to company and customer

- Each file gets an **entity**: which company it's about (target, a
  subsidiary, a portfolio company).
- **Customer contracts are tagged to the customer** when the counterparty can be
  inferred and matched to customers known from billing imports or
  connections. The source of the tag is shown, and the tag can be corrected.
  Same rule: clear match → tagged; ambiguous → asks.
- The documents view filters by category, company, customer and source
  (data room vs imported).

## 4. What's missing — ask for it

- Each pack declares its **expected inputs**: required and nice-to-have
  categories (multifamily: rent roll, T12, delinquency; SaaS: billing,
  customer contracts for the top N customers, cap table). They sit beside the
  pack's import targets and metrics.
- A **checklist** on Overview and Documents shows each expected input as
  received (with its files), missing, or covered by a connection. Gaps are
  specific where possible: "contracts for 3 of your top 10 customers by
  revenue are missing: Acme, Globex, Initech."
- **Request missing items:** one action produces the request list for the
  counterparty. In a pact with a seller-side guest (ADR 0014), it's a request
  inside the pact. Files that arrive (in the data room or uploaded) tick the
  checklist off as intake classifies them.

## 5. Connected data takes its own path

- When a category is fed by a data connection (GitHub → code and delivery,
  Jira → delivery, billing provider → invoices), the checklist shows it as
  **connected** (last sync, coverage) and doesn't ask for files. If a
  connection and a file both exist, the connection wins for the numbers and
  the file stays as a document.
- Connections are offered where the gap appears ("Delivery data missing.
  Connect Jira, or upload an export").

## 6. Demo data in the same shape

- Restructure `kuramach/pactlab-demo-data` so each pack's scenario is what a
  seller actually hands over: a **data-room folder** (to sync through
  the document-source fixture adapter and to browse) and the same content as
  **`dataroom.zip`** (for the no-data-room path). Mixed, real-looking files
  with inconsistent names, plus deliberate tests: two gaps, one duplicate,
  one misfiled document, one genuinely ambiguous file the AI should ask about,
  and customer contracts naming synthetic customers that match the billing
  data.
- GitHub and Jira data (T-094 B8) stays **outside** the data room, loaded
  through the connection path.
- Each scenario's README lists what intake should conclude: categories,
  customer tags, the gaps, and the one question it should ask. That list is
  the e2e expectation. Keep it in step with the in-repo synthetic fixtures
  (T-082 style); regenerate via `scripts/demo-data/generate.py`.

## Guardrails

- **Rule 2 holds where it matters.** Classifying and routing a file is
  automatic. Anything that becomes an accepted finding, a valuation input or
  a price still passes its existing human gate (finding review, T-094 B9
  confirmation for debt and cash). Auto-digested numbers show as
  "from <file>, classified by AI" until confirmed, and the bridge marks
  which inputs are unconfirmed. If an existing gate turns out to block
  "digest automatically", stop and flag it in the PR for Kumar. Don't remove
  the gate.
- Read-only access to data rooms and drives. Pactlab never writes, moves or
  shares files at the source.
- AI-excluded data classes are never sent for classification. They're filed
  by name and extension only and listed as needing a person.
- Every step shows its state per file. A failure is announced when it
  happens.
- Side-scoped confidentiality is unchanged.

## Retest checklist

1. Connect the software-saas demo data room (fixture): every file indexed,
   pulled, classified with confidence; the duplicate shown once; the
   ambiguous file and the misfiled one in "Pactlab needs you" with a clear
   question. Nothing else asks for a click.
2. Billing goes into the import mapping, the balance sheet into debt and cash,
   contracts into extraction and tagged to customers. All of it happens with
   no per-file labelling.
3. Add a file to the room and re-sync: only that file goes through intake.
   Remove one: it's marked removed, and its findings keep their lineage.
4. Same scenario via `dataroom.zip` with no data room: same result.
5. Checklist names the deliberate gaps. "Request missing" produces the list;
   with a seller guest, their upload ticks one off.
6. GitHub/Jira show as connected, not missing. Disconnecting turns them into
   gaps with "connect or upload".
7. Repeat 1 with multifamily and commercial-property: rent roll, T12 and
   CAM go to their import targets.
