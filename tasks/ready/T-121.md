# T-121 — Vision model lane: charts, scans, and image evidence in document intake

Model: opus
Engine: claude
**Lane:** platform (AI)
**Context:** deep
**Touches:** packages/ai (models, gateway, prompts, evals), apps/api (document intake pipeline), packages/domain (evidence types), packages/db (evidence storage), infra/config (model env wiring), docs (ADR)
**Needs:** T-096 (always-on AI: queued jobs, retries, fallback, circuit breaker — the vision pass runs as a queued job on that machinery; parts not yet built can land with compatible seams)

## Why

Direction from Kumar (2026-11-12), after a practitioner's hands-on report
that a strong vision-language model (NVIDIA Nemotron Super VL 120B) leads
their model lineup across use cases: Pactlab's evidence is documents all
the way down, but the pipeline is text-only. Anything that arrives as an
image is effectively invisible or degraded today:

- **Charts and graphs** in CIMs, decks, and financial documents (revenue
  bridges, cohort charts, occupancy trends) — the numbers live in pixels.
- **Scanned pages** — leases, financial statements, signed documents
  where OCR loses tables, stamps, and layout semantics.
- **Image tables** — statements and schedules rendered as images.
- **Photos** — property condition in the multifamily / commercial packs.

The architecture needs a first-class vision lane, not a one-off call.

## What

1. **A VISION tier in the app's model routing.** Add a vision alias
   alongside the existing FAST / BALANCED / DEEP_REVIEW tiers in
   `packages/ai` model config, env-overridable exactly like the others
   (e.g. `BEDROCK_MODEL_VISION`), resolved through the existing provider
   seam. First candidate: Nemotron Super VL (the practitioner-validated
   leader); the task's first step is a reachability decision — Bedrock
   listing / hosted endpoint / other managed route — recorded in an ADR.
   Do not hardwire a model that has no managed serving path, and do not
   self-host GPU serving in this task: integrate the strongest reachable
   vision model behind the seam.
2. **A vision pass in document intake (ADR 0016 pipeline).** The
   document classifier already routes pages; extend routing so pages
   classified as chart-bearing, image-table, scanned, or photo go
   through the vision model. Output is **normalized evidence**, cited to
   document + page, in the same evidence model as everything else:
   - chart -> extracted data series (table) + a plain-language summary,
     values labelled as extracted-from-image;
   - image table -> structured table;
   - scanned page -> text + layout notes (stamps, signatures, tables);
   - photo -> description + any visible text.
   Each vision evidence item keeps a reference to its source page image
   so a reviewer can check the extraction against the original in one
   click.
3. **Downstream consumption, unchanged rules.** Vision evidence feeds
   document Q&A and the findings flow like any other evidence. It does
   not become a finding by itself, and it gets no special valuation
   treatment: if a new evidence type is introduced it registers in
   VALUATION_DIRECTION_MAP with an explicit direction and rationale
   (expected: chart/scan data lands as FINANCIAL evidence under
   existing finding types, i.e. no silent new price paths).
4. **Degradation and cost control.** If the vision provider is
   unavailable, intake falls back to today's text/OCR path and flags
   the affected pages as not vision-processed (T-096 fallback /
   circuit-breaker patterns) — intake never hard-fails on vision.
   Vision runs only on routed pages (never whole documents by default),
   with a per-document page cap; usage is metered per pact like other
   AI spend so per-deal cost stays visible.
5. **Evals before trust.** Add vision cases to the packages/ai eval
   harness: synthetic charts rendered from known data (exact ground
   truth), image tables, and scanned-style samples. Report series-value
   extraction accuracy and table-structure accuracy for the chosen
   model against the eval set; the lane ships behind those numbers,
   not on vendor claims.

## Guardrails

- The vision model extracts; it does not opine. No findings, directions,
  or valuation inputs come from the vision model directly — only
  evidence that flows through the normal review machinery.
- Extracted-from-image values are always labelled as such in evidence
  and in any UI/report surface that shows them, with the source page
  one click away. Never present a chart-extracted number as if it were
  read from a data file.
- Confidentiality is unchanged: deal documents go only to the
  configured provider for the org's environment; no new external
  service is introduced without the reachability ADR naming it.

## Acceptance

- A document containing a chart produces a cited evidence item with the
  extracted series + summary; a reviewer can open the source page from
  the evidence item; document Q&A can answer from it and cites it.
- Vision tier is swappable by env config alone (same pattern as the
  other tiers); with vision disabled/unavailable, intake completes on
  the text path and flags unprocessed image pages.
- Eval report in the PR: extraction accuracy on the synthetic-chart
  and image-table golden sets for the chosen model, plus measured cost
  per vision page.
- Per-pact AI usage shows vision spend as its own line.
- ADR records the reachability decision (which vision model, served
  how, and the fallback) and the evidence-type registrations.
