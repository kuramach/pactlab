# T-178e — Pactlab Rinse: the window, the pinned converters and the first installers

Engine: claude

Checks: pnpm lint && pnpm typecheck && pnpm test

## Why
T-178b (#341) wired the Tauri shell, the engine sidecar, preparer sign-in and AI jobs, and the `rinse-desktop` workflow. It stopped short of an installer, and `docs/runbooks/rinse.md` says so:
- **The window isn't built:** `src/ui/main.tsx` isn't wired to the sidecar, so the workflow stops at the window step on purpose.
- **The converters aren't pinned:** `apps/desktop/converters.lock.json` has no release URLs or SHA-256s, so the app fails closed (`TOOL_MISSING`).
- **No installer has been produced.** There's no Rust toolchain on the local machine; GitHub's macOS, Windows and Linux runners have one.

## Build
1. **The window:** `src/ui/main.tsx` mounts the existing Rinse screens (T-178, and T-178d's cloud destinations) and talks to the sidecar over its one-JSON-request-per-line protocol.
   - **The screens:** sign-in, open a folder, rinse with progress (the animated flask), the gap list, hand entry, write the finished folder, and upload to the seller's own storage.
   - **Look:** the approved patterns and the Pactlab identity from T-178's "Look, motion" section, with reduced motion honoured.
2. **Pinned converters:** pin LibreOffice and Tesseract per target (macOS arm64 and x64, Windows x64, Linux x64) in `converters.lock.json`.
   - **Source:** each project's own official release page or download mirror, with the SHA-256 the build checks. Verify every URL and hash against the project's published checksums; invent nothing.
   - **Licences:** their licence texts go into the app's notices (MPL-2.0, Apache-2.0).
3. **The first installers:** run the `rinse-desktop` workflow end to end on GitHub's runners.
   - **Signing:** builds are **unsigned** until Kumar's Apple Developer and Azure Artifact Signing identities exist; `SIGNING.json` says so honestly.
   - **Updater:** generate no updater keys here. That's Kumar's step, done through `rinse-signing-setup.sh`.
   - **Records:** the run's artifacts and `SHA256SUMS.txt`.
4. **The release feed:** publish the `pactlab-rinse-releases` v1 feed that T-178c's page reads, marking each asset `signed: false` until it's signed. Document the release steps in the runbook.

## Acceptance
- The workflow produces installers for all four targets from CI, each with its checksum and `SIGNING.json`.
- On macOS, the unsigned app opens via right-click → Open; on Windows, through SmartScreen's "More info → Run anyway". It rinses the `harbour-lane-rinsed` fixture end to end, offline, with the bundled converters.
- `pactlab.ai/rinse` lists the release from the feed, marked unsigned.
