# T-172 — Web app internationalization: framework, string externalization, locale per user

Engine: claude
Model: opus
Lane: web
Context: deep
Touches: apps/web packages/ui packages/contracts apps/api docs tasks
Needs: T-170
Checks: pnpm lint && pnpm typecheck && pnpm test && pnpm test:integration && pnpm test:fixtures && pnpm test:e2e
**Needs note:** builds on T-170's single formatter so dates, numbers and money localize through one path.

## Why

The product itself must speak the target markets' languages (Kumar, 2026-11-26): Japanese, German and French, alongside English. Today the web app has no i18n library and user-facing strings are inline. This task builds the framework and externalizes every string; T-173 then translates. Splitting framework from translation keeps each reviewable.

## Build

1. **Framework:** one catalog system for apps/web and packages/ui (the same library/conventions as the site, T-171), locale resolved per user (profile setting) with an org-level default, English as source locale. Locale set at launch: en, de, fr, ja.
2. **Externalization:** every user-facing string in the app moves to the catalog — navigation, pact surfaces, findings, valuation, terms, imports, settings, admin, error and empty states, and the What's-new/feature-card system. No user-facing literal remains outside the catalog (a lint/CI check enforces it for new code).
3. **Formatting through T-170:** all dates, numbers and money render through the shared formatter with the user's locale and the pact's currency — locale and currency are independent axes (a German user can view a JPY pact; the language is German, the money stays yen).
4. **Pilot locale proof:** German catalog completed for one full surface (the pact home + findings) to prove the pipeline end to end, including pluralization, date formats and long-string layout; the remaining surfaces' German and all other locales are T-173.
5. **API-facing text:** API error messages that reach the UI carry message keys, not prose, where the UI renders them; email/document text is T-174's scope, not this task's.

## Checks

- Catalog completeness and no-literal checks in CI; existing e2e suite green in English; the pilot surface's e2e runs in German.
- Type-safe message keys (a renamed key fails typecheck).

## Acceptance

- Switching a user to German renders the pilot surface fully in German with correct formats; switching back is instant.
- The no-literal lint rule is on, and the English catalog is complete for the whole app.
- A short ADR records the framework choice and the locale model (user over org over default).
