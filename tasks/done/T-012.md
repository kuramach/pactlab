# T-012 — Valuation persistence (schema, RLS, repository, mount)

Status: done
Needs: T-005, T-011
Touches: packages/db apps/api/src/valuation apps/api/src/app.module.ts tasks
Lane: valuation
Checks: pnpm lint && pnpm typecheck && pnpm test && pnpm test:integration

## Why

T-005 shipped scenarios, runs, staleness and frozen submissions against an
in-memory port; `ValuationModule` was never mounted. Increment 4's exit
criterion ("changing an accepted risk marks dependent scenario results
stale") was only true in tests.

## Plan

1. **Migration `20261005000100_valuation`** (expand-only):
   `valuation_scenarios` (status/version columns mutable),
   insert-only `valuation_assumption_sets` (JSONB values of decimal strings,
   unique per scenario+version), `valuation_runs` (full resolved inputs +
   result), `valuation_submissions` (canonical text + digest, **CHECK
   `digest = sha256(canonical)`** so frozen bytes cannot drift),
   append-only `valuation_submission_decisions`.
2. **Privileges:** SELECT/INSERT everywhere; UPDATE only
   `valuation_scenarios(status, assumption_version, updated_at, version)`;
   no DELETE.
3. **RLS:** tenant + deal + `app_is_buyer_side`. Actor columns
   (`created_by`, `ran_by`, `submitted_by`, `decided_by`) must equal the
   caller. **Four eyes in the database:** a decision is rejected when the
   caller submitted that submission.
4. **`PrismaValuationRepository`** in `apps/api/src/valuation`: every call in
   `withTenant`; scenario compare-and-set + appended record + audit event in
   one transaction. JSONB key reordering is harmless because submissions
   store the canonical string and canonical JSON sorts keys.
5. **Mount** `ValuationModule` in `AppModule`, sharing the findings
   repository instance with `FindingsModule`.
6. **Tests:** valuation API suite runs on the production app + PGlite (in-memory
   doubles removed); DB tests for isolation, contributor denial, digest CHECK,
   four-eyes, immutability; real-Postgres cross-tenant case.

## Acceptance

- `/v1/deals/:id/valuation/scenarios[...]` served by `AppModule`.
- Re-pricing an accepted finding marks a persisted scenario stale; frozen
  submission bytes are identical on re-read after approval.
- Checks green.

## Rollback

Drop the five `valuation_*` tables and `scenario_status` /
`submission_decision` enums; nothing else depends on them.

## Out of scope

Documents persistence (T-013); outbox consumer for proactive staleness
(staleness is computed at read time from current finding versions).
