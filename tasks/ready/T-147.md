# T-147 — Document sources: real OAuth connect for Google Drive, OneDrive and Box (no pasted tokens)
Model: opus
Engine: claude
Lane: platform
Context: deep
Touches: packages/connectors packages/config packages/db apps/api apps/web docs tasks
Needs: none
**Needs note:** builds on T-098 (document sources and the connect UI) and T-126 (version-aware sync), both in tasks/done/. The sync engine and the DocumentSourceAdapter list/download contract do not change; this task changes how credentials are obtained and adds the Box adapter. Kumar asked for the clean version on 2026-11-21, for Google Drive, OneDrive and Box alike.

## Why

Today a LIVE document source connects by pasting a provider access token into the pact's Documents page. The token is stored in the secret store and reused at sync — but a Google or Microsoft user access token lives about an hour, so a source quietly starts failing with SOURCE_ACCESS and the only remedy is pasting a fresh token. That is a v1 shape, not a connection. Sellers keep deal documents in Drive, OneDrive/SharePoint and Box; connecting a folder to a pact should be: sign in once, pick the folder, and Pactlab keeps itself connected. Box is not a document-source provider at all today (providers are google-drive, onedrive, vdr), so it needs the adapter as well as the connect flow.

## Shape

1. **Org-level provider connections (the connections module).** One OAuth 2.0 authorization-code connection per provider per organization:
   - Google Drive — scope `https://www.googleapis.com/auth/drive.readonly`, `access_type=offline` so a refresh token is issued.
   - OneDrive / SharePoint — Microsoft identity platform, delegated `Files.Read` + `offline_access` (Graph driveItem children + /content, as ADR 0016 records).
   - Box — OAuth 2.0 with the read-only scope `root_readonly`.
   - The refresh token goes to the secret store under a per-organization, per-provider reference. Access tokens are minted and refreshed automatically at sync time; nothing about a token is ever returned by an API or shown after connect (the rule the pasted token already follows).
   - Connection state is visible in the org's connections UI: provider, connected account label, status (connected / reconnect needed). Disconnect deletes the stored credential.
2. **Document-source connect uses the org connection.** Connecting a source becomes: choose the provider, choose (or start) the org connection, give the folder id. The per-pact credential reference is replaced by a reference to the org connection; the folder config and everything downstream (T-126 sync: version compare, read caps, whole-set semantics) are unchanged.
   - The pasted-token field leaves the web UI for LIVE sources. Existing token-based sources keep working until their token dies, then surface reconnect-needed and are reconnected through OAuth — no forced migration mid-deal.
   - Fixture mode is untouched (local/dev synthetic rooms).
3. **Box document-source adapter** (`packages/connectors/src/document-source/`), implementing the existing DocumentSourceAdapter contract:
   - Provider id `box`, label "Box", registered in DOCUMENT_SOURCE_PROVIDERS / DOCUMENT_SOURCE_LABELS / DOCUMENT_SOURCE_SCOPES.
   - List: Box API folder items, recursive, paginated (offset or marker per the API), folders descended the same way the Drive adapter descends its folder.
   - Read: file download endpoint; change detection from the file's etag/version fields, mapped onto SourceFile.version exactly as Drive's version and Graph's cTag already are.
   - Files the connected account cannot read surface as sync errors for that file, never silent skips; unsupported types follow the existing SKIPPED path.
4. **Provider app registrations (prerequisites, Kumar's accounts).** The build proceeds against recorded fixtures; live use waits on one registration per provider, each documented in the ADR/runbook with its per-environment redirect URIs:
   - Google Cloud OAuth client in the pactlab project (web application).
   - Microsoft Entra app registration (delegated Files.Read, offline_access).
   - Box app in the developer console (OAuth 2.0, root_readonly).
   - Client ids and secrets are configuration, never code: env schema in packages/config following the existing provider-key conventions, and a `scripts/doc-source-key.sh`-style helper per environment that stores them to Secrets Manager on the ai-key.sh / signing-key.sh pattern.

## Failure behaviour

- A revoked or expired refresh token puts the connection and its sources into a visible reconnect-needed state (the existing SOURCE_ACCESS surface) — never a silent stall, never a retry loop against the provider.
- Sync stays strictly read-only: no write, move, share or delete call exists in any adapter, before or after this task (ADR 0016).

## Guardrails

- **Read-only scopes only** — the standing rule for every Pactlab connection and ADR 0016's design. A contract test pins the exact scope set requested per provider (DOCUMENT_SOURCE_SCOPES plus `offline_access` where the provider requires it for refresh); adding a scope fails the build.
- Tokens live only in the secret store; never logged, never in a URL, never returned by an API.
- CI never calls a live provider (standing rule): OAuth and adapter behaviour are proven against recorded HTTP fixtures, and the fixture-room e2e flow is unchanged.
- Box files enter through the same intake path as every other source (scan, pages, retention, then intake) — no Box-specific side door.

## Acceptance

- In a test tenant, each provider connects via the OAuth flow against fixtures, a folder is attached to a pact, and a sync imports its files end to end.
- A sync run after the access token has (simulated) expired succeeds through the refresh path with no user action.
- Revoking a connection flips its sources to reconnect-needed and the next sync reports SOURCE_ACCESS instead of reading anything.
- Box: the shared adapter contract suite passes for the Box adapter, including pagination, version-change re-read, and unreadable-file error surfacing.
- Existing google-drive / onedrive sources and the T-126 sync tests pass unchanged.
