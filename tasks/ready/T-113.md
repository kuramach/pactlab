## Why

The platform's tests are API/integration tests, and they are good. The Playwright suite in apps/e2e exists but has been flaky-red since late October 2026 — identical code passes and fails on different runs — so it is not trusted as a gate and UI flows have no reliable coverage. The fix is not more tests on a flaky base; it is trust first, then a small set of critical-journey tests, then deterministic AI coverage.

## Part 1 — Instrument, quarantine, stabilise CI config

- Turn on flaky visibility: the CI report must list every test that passed on retry. That list, sorted by frequency, is the de-flake work queue.
- Quarantine the worst offenders immediately: out of the gating suite into a non-blocking quarantine job, each with a named owner and a fix-or-delete date (<= 10 working days, cap ~8 quarantined at once).
- CI config for the gating suite: retries 2 (CI only), trace on-first-retry, screenshot only-on-failure, video retain-on-failure, workers 1-2, Chromium only, Linux. Artifacts upload only on failure.

## Part 2 — De-flake the core patterns

- Locators: getByRole -> getByLabel/getByText -> getByTestId. Designer CSS classes and XPath are banned in specs; use codegen to pick locators.
- Waiting: web-first assertions only. Ban waitForTimeout, networkidle readiness waits, and non-retrying isVisible() checks (lint or review-enforced).
- Isolation: per-test unique data (UUID-suffixed tenants/users/documents), seeded and torn down via the API request fixture, never via UI clicks; no shared mutable seed data for write tests; no order dependence.
- Auth: setup project logs in once per role/tenant persona, storageState reused by tests; API login in setup, not UI login.
- Stub every third party; pin timezone/locale/viewport in config.
- Burn-in: every new or fixed E2E test runs --repeat-each 20 before it may join the gating suite.

## Part 3 — Shrink and tier the suite

- Audit every existing spec: if an API or component test can prove it, push it down or delete it. What remains is the critical-user-journey set (~5-15): sign-up/sign-in by email code, tenant isolation through the UI, create pact, upload document -> analysis -> findings, review a finding, run a valuation, propose a term, invite a counterparty. Tag: @smoke, @regression, @prod-safe.
- Tiers: PR = @smoke plus --only-changed (fetch-depth: 0; it is a heuristic, never the only run); merge to main = full Chromium suite; nightly = full suite, sharded (matrix + blob reporter + merge-reports).
- E2E runs against a production build (webServer: next build && next start), never next dev.

## Part 4 — Deterministic AI in E2E; evals stay separate

- The AI provider stays behind its existing provider seam; add a mock/fixture provider for the test environment (an in-repo fixture server or a recorded-response double in the TanStack AI / aimock pattern: per-test fixture routing so parallel tests do not collide). CI E2E must make ZERO live model calls — prove it in the test report.
- Rewrite AI-flow assertions: response schema/shape, allowed finding categories, and outcome probes (query the API/DB afterwards: the finding exists, with the right tenant, document and severity). Delete every assertion on exact model prose. Assert streaming completion signals, never partial text.
- Stand up the separate eval suite skeleton (code-owned harness; NOT Playwright): 20-50 tasks built from real documents and real failure modes, code-based graders first; it runs on prompt/model changes and nightly, non-gating. LLM-as-judge may be added later, calibrated against human labels — not in this task.

## Part 5 — Environments: stage gates, production smoke only

- Separate Playwright projects for staging and production (baseURL, tags, timeouts).
- The full mutating suite runs against staging on deploy and gates promotion to live.
- Production: a dedicated synthetic tenant + accounts (excluded from analytics, billing and outbound email), and a post-deploy job running only @prod-safe read-path journeys. Failure triggers the rollback decision, not a shrug.
- Synthetic monitoring (running @prod-safe on a schedule) is explicitly NOT in this task — it waits until the production smoke flake rate is under ~2-3% sustained.

## Acceptance

- The gating E2E suite is green on main for 10 consecutive CI runs with zero pass-on-retry tests in the gating set.
- The PR smoke tier completes in ~5 minutes wall-clock or less.
- The quarantine list exists in the repo with an owner and date on every entry; nothing sits in quarantine past its date.
- AI journeys run in CI with zero live model calls, verified from the mock/fixture provider's request log.
- The tier table (which suite runs where, and what it gates) is documented in the repo.
