# T-045 — 3D iconography: 3dicons on the marketing site and app empty states

Status: ready
Needs: none
Touches: apps/site apps/web packages/ui tasks
Lane: web-ux

## Decision (how 3D icons are included in Pactlab — follow this, don't re-litigate)

- Source: **3dicons** (3dicons.co) only. Free for commercial use, one
  consistent single-author set. Never mix in a second 3D library — a missing
  subject means no art in that slot, not a substitute from another set.
- One finish, one angle, platform-wide: pick the glossy/gradient finish whose
  palette sits closest to the brand indigo (#6978ff) on navy (#081127) and use
  it for every icon, site and app. Consistency is the design value here.
- Static PNG renders, self-hosted in the repo. No runtime 3D (no three.js /
  glTF in the bundle for icons), no CDN hotlinks — CSP, reliability and
  licensing hygiene. Ship one 512px master per icon (displays at ≤256px, so
  retina is covered); compress to ≤60 KB per icon; ≤10 icons per page.
- Decorative only: `aria-hidden`, empty alt, always paired with a visible text
  label. Fixed width/height on the `<img>` so nothing shifts layout; lazy-load
  below the fold.
- Placement whitelist: marketing-site module/feature sections, industry pages,
  hero-adjacent art; in the app, empty states and onboarding only.
  Blacklist: tables, nav, buttons, tabs, and any slot under 32px — those stay
  line icons. Brand logos (T-042) stay flat SVG; 3D never applies to them.
- Record provenance: an `ASSETS.md` next to the icons with source URL, finish,
  and download date.

## Work

- Curate the set: one icon per platform module (the 13 modules in the site
  content, `apps/site/lib/content.ts`) plus the app empty states that need one
  (evidence, sources, deals). Download once, commit the PNGs under
  `apps/site/public/illustrations/3d/` and `apps/web/public/illustrations/3d/`.
- Registry: a key → asset map per app (site: alongside `apps/site/lib/icons.ts`;
  web: a `_lib` module), with a contract test — every module/empty-state key
  resolves to a committed asset file, a missing file fails the build (same
  pattern as T-037/T-042).
- Component: extend the site's `components/icon.tsx` pattern with a `ModuleArt`
  renderer for the 3D assets; in `packages/ui`, give `EmptyState` an optional
  `art` prop (asset key/src) so app pages opt in without new markup.
- Wire it up: site product/features sections and industry pages render the art
  for each module; the evidence, sources and deals empty states in the app use
  it. Nothing else changes visually.
- Tests: the registry contract tests above; a site content test that every
  module has an art key; an EmptyState test for the optional art rendering.
