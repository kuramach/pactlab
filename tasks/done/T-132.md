## Kumar's direction (2026-11-17)

"Use your analysis and apply various models for the best-of-breed work where it is needed." Instead of standardizing the product on one provider, route each pipeline job type to the frontier model the current evidence says is best at that job.

Evidence base (Muse's analysis to Kumar, 2026-11-17, from 2026 independent benchmarks):
- ContractScrub (Aug 2026), final contract proofread (misused defined terms, broken cross-references, wrong party names, contradictions): recall GPT-5.5 75%, Gemini 3.1 Pro 74%, Claude Sonnet 69%, Claude Opus 62%. Reasoning mode adds 9–11 points.
- "A Few Good Clauses" (May 2026), extraction of 26 standard contract fields: Gemini 3.1 Pro and Claude Opus tied at 82%, Sonnet 80%, GPT-5.4 78%.
- Long-document processing tests (25,000 documents): Claude first on extraction accuracy and careful long-context reasoning; Gemini first on visual-heavy PDFs (reads each page as an image natively, no separate OCR) and on cost — ~$0.19 and ~90s per contract vs ~$1.38 and ~9 min for GPT-5.5 with reasoning.
- FinanceBench-style systems work: pipeline architecture swings results far more than model choice (same model ~76% full-context vs ~87% in a well-built agentic system; naive vector RAG 19–50%). Models locate and cite; deterministic code keeps doing the arithmetic.

These assignments are DEFAULTS, not doctrine. The registry below makes each one a config value the eval harness can overturn without a rebuild.

## The routing (defaults)

| Job type | Default lane | Why |
|---|---|---|
| deep_review — findings judgment on agreements | Claude Opus class | Extraction accuracy + careful reasoning; the current deep_review choice, kept |
| contract_scrub — NEW pass: defined-term / cross-reference / party-name consistency over agreements | GPT-5.5, reasoning on | ContractScrub recall leader |
| extraction, classification, first-pass document Q&A (the volume work) | Gemini 3.1 Pro | Tied-first extraction at a fraction of the cost; protects the per-deal AI cost target ($3.50–$10.50) |
| vision extraction — scans, lease exhibits, charts, image tables (the T-121 VISION tier) | Gemini 3.1 Pro native document vision | Managed path, best visual-document results; answers T-121's reachability ADR — Gemini first, Nemotron/Qwen VL remain eval challengers, no self-hosted GPUs |
| fast — cheap classification / triage | Haiku class or Gemini Flash class | Pick per current pricing at build time; the registry decides |

## Build

1. **JOB_MODEL_MAP registry** (same pattern as VALUATION_DIRECTION_MAP): job type -> (provider, model id, params). Every pipeline job type must be registered; a contract test fails the build on an unmapped job type. Per-job env override (e.g. `MODEL_JOB_DEEP_REVIEW`) without code change. This registry is the data T-131's admin console surfaces.
2. **Per-job provider seam.** Today `AI_PROVIDER` is global. Extend the T-096 resilient gateway so the provider is selected per job: Bedrock (Claude, when unblocked), Anthropic direct API (Claude, interim), Vertex AI US region (Gemini), Azure OpenAI US region or OpenAI direct (GPT). Each job type declares a fallback chain; a provider that is unconfigured or down degrades along the chain and the substitution is logged and metered — never a silently dropped job (T-125 no-silent-failures rule).
3. **One evidence contract for all providers.** Every lane returns through the same normalized-evidence and citation machinery. No provider bypasses the citation gate ("no citation, no accepted finding"). Structured-output shapes are normalized at the seam, not in callers.
4. **Cost metering per job type per pact**, rolled into the existing per-deal AI cost view. A job that would breach the per-deal cost ceiling degrades to its fallback lane and flags the fact; it never just spends.
5. **Data terms.** US data residency where the provider offers it; enterprise / no-training terms only; customer document content is never sent to a consumer-tier endpoint. Credentials live in env/secret config per environment, alongside the existing Bedrock settings.
6. **Smoke verification per lane (explicitly NOT a bake-off).** A small fixed set of synthetic documents with known answers — an agreement with planted defined-term errors (scrub), a lease with an image table (vision), a financial statement (extraction), a clean agreement (deep review) — run in CI against the fixture provider, plus a manual live smoke per configured provider before that lane is enabled in an environment. The eval harness remains the mechanism that can re-rank defaults later; a re-rank is then a registry change.
