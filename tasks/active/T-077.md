# T-077 — One findings register: document findings are priceable (pilot bug 11)

**Lane:** core
**Context:** standard
**Touches:** api (findings, documents), db (findings filter), web (findings, documents)
**Needs:** T-076

## Why (Kumar, 2026-10-24)

Accepted document-AI findings lived only in the Documents review queue, so they couldn't be priced or reach valuation.

## Done

- **On acceptance** (a human decision), the claim becomes a register DRAFT finding:
  - origin AI, domain LEGAL;
  - its evidence is the same document citations, re-verified;
  - created once, with fingerprint `document:<id>`.
  - The reviewer then decides its direction and price in the normal Findings flow. Nothing is priced automatically.
- **Accepted findings from before this change:**
  - `GET` and `POST /v1/deals/:id/findings/from-documents` report how many are pending and bring them in (idempotent);
  - the Findings page shows a "Bring them in" banner.
- **Permissions:** reviewers who accept may bring findings in, as may anyone who drafts findings.
- **Findings page:**
  - a "Source: document review" filter;
  - a "From document review" badge on those findings.
- **Documents page:** accepted findings link to the register.
- **No schema change:** the fingerprint links the two records, unique per deal.

## Checks

`pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm test:e2e`.

A browser spec waits for a seeded accepted document finding: AI is off in e2e. The API tests cover the flow.
