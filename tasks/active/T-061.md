Lane: packs
Context: standard
Checks: pnpm lint && pnpm typecheck && pnpm test && pnpm test:integration && pnpm test:fixtures

Build the Healthcare services and healthtech pack on the T-057 framework (definition: spec §19 and
ADR 0008 where it applies). Start with the §19 spec amendment the activation
bar requires: import targets, finding types, valuation adjustments, fixtures
and the acceptance journey below.

## Import targets (CSV, ADR 0010)

Column layouts match the published demo data
(`kuramach/pactlab-demo-data/healthcare/`), so its files import as they are:
  - `claims-summary.csv — claims billed, paid and denial rate by payer`
  - `provider-roster.csv — pseudonymous provider roster with credential expiry`
- plus the billing import on the Pactlab standard template, unchanged.

## Finding types (deterministic detection → draft findings, humans decide)

  - Revenue concentrated in government programmes
  - Medical-director fee above documented duties (agreement vs time records)
  - Privacy risk assessment out of date
  - Provider credentials expiring

## Valuation

  - Payer-mix and reimbursement-rate sensitivity
  - Healthtech targets also run the software path

No patient-level data is accepted; provider data is pseudonymous and never
sent to a model (rule 7).

## Acceptance

- Import every file in `pactlab-demo-data/healthcare/<USD|EUR|GBP>/` into a
  fresh deal with that pack and base currency; each planted finding in that
  folder's README surfaces as a cited draft finding, and accepting it reaches
  the valuation with the stated direction.
- Extend the demo-data contract test (`apps/api/src/ops/demo-data.test.ts`)
  so this pack's extracts import cleanly through their targets.
- Synthetic data only.

## Out of scope

- Direct connections to industry systems (property-management, PMS/STR,
  core-banking, EHR/RCM, …). Packs start with file imports (Kumar,
  2026-10-22); live adapters come later behind the same import targets.

## Done (2026-10-25)

- Targets `HEALTHCARE_CLAIMS_SUMMARY` (keyed by month + payer via the new `recordIdFields`) and `HEALTHCARE_PROVIDER_ROSTER` (pseudonymous); expand-only migration `20261031000000_healthcare_pack`.
- Shared rule factories in `packages/calculations/src/packs/common.ts` (`revenueConcentrationRule`, `documentClauseRule`) for the remaining packs.
- Four rules: government concentration, director fee (indemnity, holdback on the bridge), privacy assessment, credentials expiring (dated by billing or, without it, the claims summary).
- Payer-mix and reimbursement-rate sensitivity use the existing scenario sensitivities; no new valuation engine (spec §19 2a).
- Acceptance `apps/api/src/packs/healthcare.acceptance.api.test.ts`; e2e `apps/e2e/specs/healthcare-pack.spec.ts`; demo-data README hints checked by `demo-data.test.ts`.
