**Needs note:** needs T-170's formatter for money and T-172's catalog conventions for shared terms.

## Why

Localization that stops at the screen fails in the markets Kumar chose (2026-11-26): the digest emails, sign-in and notification emails, and the generated artifacts a deal team actually circulates — reports, QoE summaries, LOI drafts, counterparty views — must arrive in the recipient's language and the pact's currency.

## Build

1. **Emails:** every outbound template (sign-in codes, notifications incl. T-145/T-146 alerts, triage digests from T-150/T-157, invites) renders in the recipient user's locale (org default otherwise), with money and dates through T-170's formatter. The Pactlab signature and tagline use the T-171 approved renderings.
2. **Generated documents:** reports, exports and draft documents render in the pact's working language (a pact-level setting, defaulting to the org's locale) with the pact's currency throughout; tables and totals use the locale's number formats.
3. **AI-produced text:** AI jobs whose output a user reads (summaries, draft document requests, triage verdicts) take the target language as an explicit job parameter recorded on the run; the ADR 0034 data-terms and evaluation gates apply unchanged per model — an evaluation passed in English does not silently bless another language: the runbook records which languages each serving model was evaluated in, and unevaluated languages fall back to the evaluated default with the output labelled as such.
4. **Never translate the record:** executed/signed documents and stored evidence are never machine-translated in place; translation applies to generated drafts and views only, and a translated draft is labelled as a translation with its source language.

## Checks

- Template rendering tests per locale for the five highest-volume emails; document generation tests in de and ja with EUR and JPY pacts.
- Job-parameter tests: the language recorded on AI runs; the unevaluated-language fallback labelling.

## Acceptance

- A Japanese-locale user in a JPY pact receives sign-in, notification and digest emails fully in Japanese with yen formatting.
- A report generated for a German EUR pact is German throughout, euros formatted de-DE.
- The runbook lists, per serving model, the languages it is evaluated for.


## Pactlab branding in every language (Kumar, 2026-11-27)
- **Emails** in every language keep the branded layout from `branded-email.ts`: the logo, the colors, and the footer tagline and note (`EMAIL_BLURB`). The tagline and note are translated in the catalogs, never dropped.
  - With an organization brand kit (T-123), the "Sent with Pactlab for <org>" line is translated too.
- **Generated documents** in every language keep the Pactlab kit, or the organization's kit, exactly as in English. Fonts must cover Japanese (embed a CJK-capable font in the PDFs), so the brand never falls back to a system font.
- **Tests:** one per language that the header logo, the footer tagline and the sender name are present.
