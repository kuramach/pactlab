# T-114 — demo-pool sweep runs on the wrong ECS task definition (migrate, not seed)

Model: sonnet
Engine: claude
**Lane:** infra
**Context:** light
**Touches:** scripts/ops-task.sh only
**Needs:** nothing

## Problem (hit live 2026-11-10)

`scripts/demo-org.sh live pool` fails immediately in the ECS task:

```
ConfigError: Invalid configuration:
  - APP_WEB_ORIGIN: Invalid input: expected string, received undefined
  - AUTH_TOKEN_SECRET: Invalid input: expected string, received undefined
    at loadConfig (packages/config/src/env.ts)
    at openDemoRuntime (apps/api/src/ops/demo-org.ts)
```

## Root cause

`scripts/ops-task.sh` runs ops scripts on the **migrate** task definition, except
`src/ops/demo-org.ts`, which it routes to the **seed** task definition because the
demo organization writes documents. `src/ops/demo-pool.ts` is not in that exception,
so the pool sweep ran on migrate — which deliberately carries only migration
essentials (DB credentials), not the app runtime config. `openDemoRuntime` calls
`loadConfig()`, which requires the full API config, so the task exits before doing
any work.

The seed task definition already carries everything needed: in
`infra/cdk/lib/compute.ts` it gets `environment: { ...apiEnvironment, ... }`
(apiEnvironment includes `APP_WEB_ORIGIN`) and
`secrets: { DB_PASSWORD, AUTH_TOKEN_SECRET }`, plus the document bucket the sweep
needs when it rebuilds demos. No CDK or stack change is required.

## Fix

In `scripts/ops-task.sh`, route `src/ops/demo-pool.ts` to the seed task the same
way `src/ops/demo-org.ts` is routed (the `KIND=seed` condition). Keep every other
script on migrate.

## Acceptance

- `scripts/demo-org.sh live pool` completes the sweep in live (exit 0).
- `scripts/demo-org.sh live` (demo-org) still runs on seed; a non-demo ops script
  (e.g. `src/ops/operator.ts`) still runs on migrate.
- Diff touches only `scripts/ops-task.sh`.
