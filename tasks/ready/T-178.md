# T-178 — Document prep bench as a DESKTOP app: the seller rinses the full document set locally, closes the gaps, then uploads the finished folder

Engine: claude
Model: opus
Lane: platform
Context: deep
Touches: apps/desktop apps/web apps/api packages/connectors packages/ai packages/domain packages/contracts docs tasks
Needs: none
Checks: pnpm lint && pnpm typecheck && pnpm test && pnpm test:integration && pnpm test:fixtures && pnpm test:e2e

## Why — and why desktop (Kumar's direction, 2026-11-26, superseding the web-first shape)

Most of the time it is the **seller** who has the documents. So the prep bench is a desktop app the seller runs on their own machine: they drop the whole document set in, the app **rinses** it — converts everything to the standard format Pactlab likes, checks it, and shows every gap — the seller fixes the gaps right there (add the missing statement, re-scan the unreadable page, resolve the duplicate) and only then uploads the finished set to a folder (deal room, OneDrive, Drive, Box, or a plain local/network folder) that feeds the pact. Nothing half-clean ever leaves the seller's machine, and the seller needs no Pactlab seat and never touches the pact itself.

## Build

1. **One cross-platform app.** A Tauri shell (single codebase for macOS, Windows and Linux) in `apps/desktop`, reusing the web UI components for its screens. Signed and notarized builds with auto-update (Tauri updater); distribution is a public download page on the site. **A Pactlab login is required** (Kumar, 2026-11-26) — the same passwordless email-code / passkey auth as the web app, as a free preparer account. Two ways in: the preparer creates the free account, or the buyer sends a **prep invite** (link/QR from the pact) that creates the account and binds it to the inviting org and deal in one step. The login is what makes the upload trustworthy, and it gates three things: (1) **binding** — the finished set is stamped with the preparer's verified identity and, via the invite, its intended pact, so injection lands in the right deal and provenance names a real party; (2) **the AI rinse jobs** — classification/OCR run under that account (metered, ADR 0034 data terms, abuse control; anonymous AI access is never offered); (3) **upload to a Pactlab-hosted deal room**, when that is the chosen destination. It is not a paid seat and grants no pact access: a preparer login sees only their own bench sets and invites. The seller's OneDrive/Drive/Box sign-in inside the app is a separate auth (their cloud, their account) and never substitutes for the Pactlab login. Offline, a signed-in app still runs the local deterministic rinse from its cached session; AI steps and uploads queue until sign-in/connectivity returns.
2. **Local rinse pipeline (the core loop: rinse → gaps → fix → re-rinse until clean).**
   - *Ingest:* whole folders, bulk files, zip archives; watch-folder mode so files added to a working folder queue themselves.
   - *Convert locally:* every document becomes the canonical form — normalized PDF with extracted text and stable page anchors — using bundled local tooling (office-to-PDF and PDF normalization run on the machine); spreadsheets/statements are **not** flattened — they are flagged and packaged for the guided-import flow (T-152) at injection time. Originals are never modified; converted versions sit alongside them with a per-file conversion log.
   - *Check locally first:* corruption, exact/near duplicates (hashes), readability — deterministic checks cost no model calls and work offline. *When online,* classification into the pack's document taxonomy, metadata extraction and OCR-quality scoring run through the AI gateway as metered jobs under ADR 0034 gates (vision lane for scans); results cache on the machine so re-rinsing is cheap.
   - *The gap list:* the app fetches the target pack's expected-document list and shows completeness as a checklist — present, present-but-flagged, missing. The seller resolves each gap locally (add, replace, re-scan, or mark not-applicable with a note) and re-runs checks until the set is clean or every remaining gap carries an explicit note. **The set cannot be marked ready with an unresolved error** — warnings and noted gaps can travel, errors cannot.
3. **Upload the finished folder.** One action writes the finished set — originals, converted versions, and a `pactlab-manifest.json` (per-file: classification, metadata, check results, gap notes, conversion log, hashes) — to the destination the seller picks: a local/network folder, or **their own** OneDrive / Google Drive / Box through their own sign-in in the app. Because the destination is the seller's own account, no Pactlab write-access to anyone's cloud is needed on this path.
4. **Injection (pact side, in the web app — unchanged in spirit).** The finished folder becomes pact input two ways: (a) the folder is connected as the pact's document source through the existing read-only OAuth sync (T-147) and the manifest is read at sync time, so classifications, gap notes and provenance arrive with the files; or (b) a one-time import of the folder + manifest. Injection is always the pact-side user's explicit act; every injected document carries its provenance (original file, conversion log, manifest entry) so citations trace back to the seller's original.
5. **Walls and privacy.** Until the seller uploads and the buyer injects, the set exists only on the seller's machine and the seller's chosen folder. The app sends nothing to Pactlab except the AI job payloads when online (document content for classification/OCR under the same data terms as every AI job) and anonymous crash/usage telemetry if the user opts in. The buyer sees the set only after injection.

## Checks

- Fixture rinse: a mixed set (scan, docx, xlsx statement, duplicate, corrupt file, one missing expected document) → statements packaged for import, documents converted with page anchors, duplicate/corrupt flagged, gap listed; after the fixture gap is resolved, the set marks ready and the emitted folder + manifest verify against the schema.
- Manifest contract test: a hand-built manifest from the desktop app round-trips through the pact-side sync unchanged.
- Offline test: deterministic checks and conversion complete with the network off; AI steps queue and run on reconnect.

## Acceptance

- A seller-side user installs the app, rinses a messy 20-file set, closes the gaps the checklist names, and uploads the finished folder to OneDrive — the folder + manifest are complete and self-describing.
- The buyer connects that folder to a pact and the documents arrive classified, gap-noted and citable to their originals.
- macOS and Windows builds install from the public download page and auto-update (Linux build produced; signing status recorded honestly in the runbook).
